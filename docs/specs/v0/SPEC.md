# rt-trading v0 SPEC: 일봉 빠른 확인
> **상태**: 구현 완료. 실데이터 실행(2026-10-23)에서 두 후보 모두 통과하지 못해 v1에서 뺐다(종가 베팅 최대 낙폭 44.30%, 갭 되돌림 전체 수익 −95.80%).

상위 문서: [intent.md](../../../intent.md)

v0는 v1 후보 중 일봉만으로 계산할 수 있는 종가 베팅과 갭 되돌림을 토스 일봉으로 긴 기간 빠르게 시험한다.
목적은 v1의 정밀 백테스트(1분봉)에 넣을 후보를 거르는 것이다. v0를 통과해도 실계좌 운용 승인이 아니다.

## 0. 완결성 계약

- 토스 Open API의 일봉 조회와 로컬 파일만 쓴다. 계좌·주문 API는 호출하지 않는다.
- v1 이후 스펙의 코드, 설정, 상태를 요구하지 않는다.
- `uv run rt-trading v0-acceptance`가 네트워크 없이 7절의 기준을 확인하고, 모두 통과하면 exit 0이다.
- `uv run rt-trading v0-check`를 실데이터로 한 번 실행해 보고서를 만든다. 후보가 통과하는지는 완료 조건이 아니다.

## 1. 일부러 단순하게 한 것

v0는 후보를 거르는 단계라 다음을 단순하게 한다. 각 항목이 결과를 어느 쪽으로 기울이는지 함께 적는다.

| 단순화 | 결과에 주는 영향 |
| --- | --- |
| 수익률로 계산하고 정수 주 제약을 두지 않는다 | 소액일 때 남는 현금 때문에 실제 수익과 달라질 수 있다 |
| 수정 가격을 써서 분배금을 수익에 넣고, 분배금 세금(15.4%)은 빼지 않는다 | 종가 베팅을 연 0.3% 안팎 유리하게 본다 |
| 갭 되돌림은 1분 뒤 시가 대신 그날 시가에 호가 한 단계를 더한 가격에 산다 | 실제 1분 뒤 체결가와 달라 결과가 유리하거나 불리해질 수 있다 |
| 손실 한도를 시뮬레이션하지 않는다 | 최대 낙폭으로만 판정한다 |
| 자산은 매매가 끝날 때만 평가한다 | 장중 낙폭은 보이지 않는다 |
| 노이즈 영역 돌파는 넣지 않는다 | 1분봉이 필요해서 v1에서 시험한다 |

## 2. 데이터

- 대상은 KODEX 200(069500)과 KODEX 인버스(114800)다.
- `GET /api/v1/candles`로 일봉 원가격(`adjusted=false`)과 수정 가격(`adjusted=true`)을, 토스가 주는 가장 이른 날부터 실행일 전 거래일까지 받는다.
  응답의 `result.candles`를 읽고 `result.nextBefore`로 과거로 넘긴다.
- 인증 정보는 `.env`의 `TOSS_INVEST_CLIENT_ID`, `TOSS_INVEST_CLIENT_SECRET`을 쓴다. 토큰은 한 번 발급해 쓴다.
  - `401 token-revoked`를 받으면 재발급하지 않고 멈춘다.
  - `403`이면 토스 WTS의 허용 IP 등록을 안내하고 멈춘다.
  - `429`면 `Retry-After`만큼 기다린 뒤 다시 보낸다. 호출은 초당 15회 이하로 보낸다.
- `data/v0.sqlite3`의 `daily_candles` 표에 저장한다. 열은 `symbol`, `date`, `open`, `close`, `adj_open`, `adj_close`이고 기본 키는 `symbol, date`다.
  다시 받으면 통째로 바꾼다. `data/`는 git에서 제외한다.
- 종목마다 원가격과 수정 가격의 날짜가 같고, 날짜가 중복되지 않으며, 가격이 양수여야 한다. 어기면 판정 없이 실패한다.

## 3. 비용

- 수수료: 매수·매도마다 체결 금액의 0.0188%(`c = 0.000188`)다. v1과 같다.
- 호가 차이: 시가·종가 동시호가 체결은 0이다. 그 밖의 매수는 원가격 기준으로 호가 한 단계 위에서 체결한다.
  ETF 호가 단위는 2023-12-11부터 2,000원 미만 1원, 2,000원 이상 5원이고, 그 전에는 5원이다.
  비율 `s`는 (한 단계 위 가격 − 원가격) ÷ 원가격이다.
- 세금: KODEX 200 매매차익은 비과세다. KODEX 인버스는 이익이 난 매매마다 이익의 15.4%를 뗀다.

## 4. 후보

두 후보의 숫자는 아래 규칙으로 고정한다. 백테스트 전에 고정하고 결과를 보고 바꾸지 않는다.

### 4.1 종가 베팅 (`overnight`)

- KODEX 200 데이터의 첫 거래일부터 마지막 전 거래일까지, 거래일 t마다 KODEX 200을 t의 종가 동시호가에 사서 다음 거래일 시가 동시호가에 판다.
- 총수익 비율 `g = adj_open(t+1) ÷ adj_close(t)`이고, 수익률은 `g × (1 − c) ÷ (1 + c) − 1`이다.

### 4.2 갭 되돌림 (`gap_reversal`)

- 갭(t)은 KODEX 200의 `adj_open(t) ÷ adj_close(t−1) − 1`이다. 수정 가격이라 분배락일 보정이 따로 필요 없다.
- 기준 크기(t)는 t를 뺀 직전 20거래일 |갭|의 평균이다.
- 갭(t) ≥ +기준 크기면 KODEX 인버스를, 갭(t) ≤ −기준 크기면 KODEX 200을 그날 시가에 호가 한 단계를 더한 가격에 사서 그날 종가 동시호가에 판다. 그 사이면 쉰다.
- 그날 사려는 종목의 일봉이 없으면 쉰다.
- 같은 날 사고팔기 때문에 수익은 원가격으로 계산한다. 총수익 비율 `g = close(t) ÷ (open(t) × (1 + s))`이다.
  KODEX 200 수익률은 `g × (1 − c) ÷ (1 + c) − 1`, KODEX 인버스 수익률은 `(g × (1 − c) − 0.154 × max(0, g − 1)) ÷ (1 + c) − 1`이다.
- 시험은 KODEX 인버스의 첫 거래일과, KODEX 200의 직전 20거래일 갭을 계산할 수 있는 첫날 중 늦은 날부터 시작한다.

## 5. 지표와 통과 기준

- 후보마다 자기 시험 기간의 거래일 수를 `N`이라 한다. 자산은 1에서 시작해 매매가 끝날 때마다 (1 + 수익률)을 곱하고, 쉬는 날은 그대로 둔다.
- 지표: 전체 수익, 연환산 수익 `최종 자산^(252 ÷ N) − 1`, 최대 낙폭 `max(1 − 자산 ÷ 그때까지의 최고 자산)`, 앞 기간(처음 `floor(N/2)`거래일)과 뒤 기간의 수익, 연도별 수익, 거래 수, 승률(수익률 > 0), 거래당 평균 수익률, 비용 전 전체 수익(수수료·호가 차이·세금 없이).
- 통과 기준은 v1 SPEC 6절과 같다. 전체 수익이 플러스이고, 최대 낙폭이 20%보다 작고, 앞뒤 기간 수익이 모두 플러스면 통과다.
- 통과한 후보는 v1에서 1분봉, 정수 주, 손실 한도로 다시 확인한다. 통과하지 못한 후보는 v1에서 뺀다. 숫자를 바꿔 다시 돌리지 않는다.

## 6. 명령

| 명령 | 하는 일 |
| --- | --- |
| `uv run rt-trading v0-check` | 일봉을 받아 저장하고 두 후보를 계산한다. `data/reports/v0-{실행 시각}.json`에 저장하고 후보별 지표와 판정을 표로 출력한다 |
| `uv run rt-trading v0-acceptance` | 7절의 기준을 네트워크 없이 확인한다 |

## 7. Acceptance Criteria

손으로 계산한 작은 가상 일봉으로 확인한다. 토스에서 받은 데이터를 fixture로 커밋하지 않는다.

- 종가 베팅 수익률, 갭과 기준 크기(t 제외), 진입 조건(이상·이하·사이), 갭 되돌림 시험 시작일, 호가 한 단계(2023-12-11 전후, 2,000원 경계), 수수료, 인버스 세금이 손 계산과 같다.
- 미래 일봉을 바꿔도 그 전날까지의 신호와 수익이 바뀌지 않는다.
- 전체·연환산 수익, 최대 낙폭, 앞뒤 기간 수익, 연도별 수익, 승률, 비용 전 수익과 통과 판정이 손 계산과 같다.
- 원가격과 수정 가격의 날짜가 다르면 판정 없이 실패한다.
- `data/`가 git에서 제외된다.

## 8. 실행 전 확인할 것

- 이 컴퓨터의 공인 IP가 토스 WTS 허용 IP에 등록되어 있다.
- 같은 토스 키를 쓰는 다른 프로그램이 돌고 있지 않다. 토큰을 새로 받으면 그 프로그램의 토큰이 끊긴다.
