# PRD: v6 PRD 05 서버 실행 환경
> **상태**: 승인(2026-11-09, 사용자가 정한 대로 오라클 검토 통과로 승인)
> 상위 SPEC: [v6 SPEC](../SPEC.md)

## 의존성

- v4·v5 자동 실행과 현황 웹페이지의 방식(`v3_serve.server`, 명령을 시간 제한 안에서 따로 실행해 `run.log`에 이어 쓰기, `web`의 모양)
- PRD 01의 장 운영 정보 받기, PRD 04의 `v6-watch`·`v6-decide`·`v6-report`와 장부
- 서버 `ka1rm31`의 Docker와 `compose.yaml`, 저장소 루트의 `.env`, Codex 토큰 폴더, v5와 함께 쓰는 토스 토큰(`data/toss/token.json`, `token.lock`)

## 문제

v6는 10분마다 평가하고 매시 판단하며 매일 보고하는 일을 서버에서 계속 돌려야 한다. v5와 같은 서버·토스 키·Codex 계정을 쓰므로, 토큰을 따로 받아 v5를 끊거나 v5를 다시 만들어서는 안 된다.
사용자는 모의 계좌 상태와 판정 지표를 한 페이지에서 봐야 한다.

## 목표

1. `v6-serve`가 10분 평가, 매시 40분 판단, 매일 10:00 보고를 차례로 돌린다(SPEC 5.1).
2. 보기 전용 현황 웹페이지를 `127.0.0.1:8082`에 연다(SPEC 8절).
3. Docker 서비스 `v6`를 더하고, v5를 건드리지 않고 올린다.
4. 시작일 하루를 v5와 함께 돌려 확인한다(SPEC 0절, 5.3).

## 범위 밖

- 명령 안의 동작(PRD 04), 판단·체결·평가의 내용(PRD 02·03)

## 자동 실행

- 켜질 때 PRD 01 `fetch_calendar`로 국내·미국 장 운영 정보를 오늘 날짜로 한 번씩 받아 `paper.lock` 안에서 합친다(PRD 04와 같다). 실패하면 기록하고 계속한다.
- 10초마다 확인해 아래 일을 이 순서로, 한 번에 하나씩 `rt-trading` 명령으로 따로 실행한다. 한 일은 메모리에 기억해 같은 일을 다시 하지 않는다.

| 일 | 언제 | 시간 제한 |
| --- | --- | --- |
| `v6-watch` | 지금이 든 10분 차례를 아직 하지 않았을 때 | 차례 시작 + 9분 |
| `v6-decide --at HH:40` | 지금이 그 시의 40분 이상 45분 미만이고, 40분 차례 `v6-watch`를 마친 뒤 | 40분 + 7분 |
| `v6-report` | 지금이 10:00 이상 10:09 미만이고, 10:00 차례 `v6-watch`를 마친 뒤 | 10:09 |

- 출력은 `data/v6/run.log`에 `=== 시각 일 ===` 머리와 함께 이어 쓴다. 시간 제한을 넘기면 멈추고 `V6_COMMAND_TIMEOUT`을 적는다. 꺼져 있던 동안의 차례는 나중에 하지 않는다(PRD 04가 `missing`과 빠진 평가로 센다).

## 현황 웹페이지

- 제목은 `rt-trading v6 현황`, 머리글은 `rt-trading v6 모의 운용 현황`이고 web 스펙의 모양(`web.document`, `web.card`, `web.signed`, `web.slot`)을 쓴다. `paper.sqlite3`와 `calendar.json`, `run.log`를 읽기만 한다.

| 묶음 | 보이는 것 |
| --- | --- |
| 실행 | 자동 실행을 켠 시각, 실행 중인 일, 마지막 실행과 종료 코드, 검증 구간(시작일, 끝 시각, 지난 국내 거래일 수), 다음 판단 시각 |
| 모의 계좌 | 마지막 평가의 자산과 `수익 {+N}원 ({+x.xx%})`, 원화 현금, 달러 현금, 환율, 그 평가가 낡은 값을 썼는지와 `stale` |
| 손실 한도 | 오늘 하루 기준과 이번 주 기준, 발동한 한도, 강제 매도 중인지, 지금 막힌 이유 |
| 판정 지표 | SPEC 6절 여섯 항목의 지금 값(판단 실패 비율, 최대 낙폭, 10분 평가 비율, 빠진 00:00 평가, `stale` 수, 장부 규칙 위반 수) |
| 보유 종목 | 종목, 이름, 시장, 수량, 평균 단가, 마지막 가격, 원화 평가, 비중 |
| 오늘의 판단 | 오늘 판단 차례마다 칸(상태 색은 `ok` 정상, 나머지 실패, 아직 오지 않은 차례 대기)과 표(시각, 상태, 목표 보유, 전략 이름, 이유) |
| 오늘의 체결 | 시각, 구분(판단·강제), 종목, 방향, 수량, 금액, 통화, 수수료·세금·위험 비용·SEC Fee, 환전 |
| 실행 기록 | `run.log`의 마지막 40줄 |

- 페이지는 GET `/`에만 답하고(다른 경로 404, GET이 아닌 요청 501), 파일을 바꾸지 않으며, 파일에서 읽은 글자는 이스케이프한다. 인증 정보와 토큰은 보이지 않는다.
- 서버의 `127.0.0.1:8082`에서만 연다. 사용자는 `ssh -L 8082:127.0.0.1:8082 ka1rm31`로 본다.

## 컨테이너

- `compose.yaml`에 서비스 `v6`를 더한다. `v5`와 같은 빌드와 연결(`./data`, 읽기 전용 `.env`, `~/.trading-oracle/auth`), `profiles: ["v6"]`, `init: true`, `restart: unless-stopped`, 명령 `rt-trading v6-serve --host 0.0.0.0`, 포트 `127.0.0.1:8082:8082`다. 같은 `./data`를 연결하므로 v5와 같은 토스 토큰 파일과 잠금 파일을 쓴다.
- v6의 모든 토스 호출은 `cli.shared_token`(`data/toss/token.json`)을 쓴다. 토큰을 따로 받지 않는다.

## 서버에 올리기와 시작일

코드가 없는 운영 절차다.

1. 서버 저장소를 v6 커밋으로 맞춘다. v5 서비스는 다시 만들거나 멈추지 않는다. 돌고 있는 v5 컨테이너는 자기 이미지로 계속 돈다.
2. `docker compose --profile v6 build v6`로 v6 이미지만 만들고, `docker compose --profile v6 run --rm -T v6 rt-trading v6-acceptance`가 통과하는지 본다.
3. 사용자가 정한 시작일로 `data/v6/config.json`을 만든다(파일 600).
4. 시작일 전날 저녁에 `docker compose --profile v6 up -d v6`로 켜서 시작일 00:00 평가부터 기록되게 한다. 페이지가 보이는지 확인한다.
5. 시작일 하루가 함께 돌기 확인 날이다(SPEC 5.3). 다음 날 아침 v5 보고서의 `decisions.csv`에 그날 v5 판단 차례가 빠짐없이 있고 모두 `ok`·`capped`인지, v5 `live.sqlite3`의 정지 기록에 그날 안전 정지가 없는지, v6 `events`에 `toss_429`가 없는지 확인한다. 다음 날 10:00 v6 보고서와 그날의 판단 차례·10분 평가가 모두 기록됐는지 확인한다.
6. 어긋나면 `docker compose --profile v6 stop v6`로 멈추고 원인을 고친 뒤, `data/v6/`의 `paper.sqlite3`, `head/`, `news/`를 다른 이름으로 옮기고 새 시작일로 3부터 다시 한다.

## 가상 fixture

- 토큰 사례: 임시 루트의 토큰 파일 하나로 v5 쪽 `SharedToken`과 v6 요청 함수(PRD 01 `request`, `cli.shared_token`과 같은 경로)를 만들고, 가짜 시계로 둘 다 만료를 보게 한 뒤 스레드 두 개로 동시에 부른다. 가짜 토스는 토큰 발급 요청 수를 센다.
- 페이지 사례: `paper.sqlite3`(국내·미국 보유, 원화·달러 현금, 판단, 체결, 평가, 한도, 강제 매도, `stale`), `calendar.json`, `run.log`를 만들고, 판단 이유에 `<script>`를, `data/toss/token.json`과 `.env`에 가짜 토큰·인증 정보 문자열을 둔다.

## 필수 Acceptance

SPEC 9절의 "실행 환경과 현황" 항목을 맡는다.

- v6의 토스 호출이 v5와 같은 토큰 파일을 쓰고, 두 프로세스가 함께 만료를 보면 토큰을 한 번만 받는다.
- 현황 웹페이지는 GET 요청에만 답하고, 판단 이유 속 HTML은 글자 그대로 보이며, 페이지를 열어도 저장된 파일이 바뀌지 않는다. 인증 정보와 토큰이 보이지 않는다.

## 완료 조건 (v6 완료)

- `uv run rt-trading v6-acceptance`가 exit 0이다.
- `cli.py`와 `compose.yaml`을 바꾸므로 v0~v5와 web acceptance가 그대로 통과한다.
- 위 절차대로 시작일 하루의 모든 판단 차례와 10분 평가를 기록하고 다음 날 10:00 보고서를 만들며, 함께 돌기 확인을 통과한다.
- SPEC과 모든 PRD의 상태를 "구현 완료"로 바꾼다. 검증 구간이 다 지나는 것과 판정 통과는 완료 조건이 아니다.
