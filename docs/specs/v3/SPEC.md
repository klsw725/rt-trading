# rt-trading v3 SPEC: 언어 모델 헤드 모의 운용
> **상태**: 승인(2026-10-24), 구현 전. 사용자 결정(Codex 토큰을 trading-oracle과 함께 쓰기, 모델 `gpt-6-sol`, 모의 운용 1주, 항상 켜 둔 이 맥북의 Docker 컨테이너에서 실행하고 보기 전용 현황 웹페이지로 확인, 2026-10-28 헤드 입력에 미국 시세 요약을 넣고 2026-10-29부터 기간을 새로 셈)을 반영했다. **[확인 필요]**는 실데이터 실행 전에 확인할 사실이다.

상위 문서: [intent.md](../../../intent.md)

v3는 언어 모델 헤드가 매 거래일 개장 전에 부하 전략 하나를 고르고, 고른 부하가 그날 실제 시세로 모의 매매하는 구조를 만든다.
언어 모델은 과거 시장 결과를 이미 학습해서 백테스트가 공정하지 않으므로, intent에 따라 실시간 데이터로 주문 없이 1주 동안 모의 운용해 검증한다.
같은 기간에 단순한 규칙 헤드와 부하별 계좌를 함께 돌려 보고서에서 비교한다.
v3는 주문을 내지 않는다. 모의 운용을 통과해도 실계좌 운용 승인이 아니며, 소액 실전은 실전 매매 스펙에서 다룬다.

## 근거와 한계

- 언어 모델은 학습한 기간의 경제 지표와 주가를 기억하고, 특정 날짜 이후를 모르는 척하라는 지시로도 막히지 않는다(Lopez-Lira·Tang·Zhu 2025). 그래서 헤드는 모델이 학습하지 않은 앞으로의 데이터로만 검증한다.
- 언어 모델이 주문을 직접 만들지 않고, 미리 만든 전략 프로그램 중 하나를 고르게 하는 구조가 연구되고 있다(MetaPS 2026, 정식 출판 전). v3의 헤드-부하 구조가 이 방식이다.
- 20년·100개 넘는 종목으로 다시 시험하면 언어 모델 매매 전략은 그냥 보유보다 못했고(FINSABER 2026), 모델이 학습하지 않은 기간의 시험에서도 대부분 그냥 보유를 넘지 못했다(StockBench 2025, AI-Trader 2025). 그래서 같은 기간 규칙 헤드와 그냥 보유를 함께 돌려 비교한다.
- 2009년 9월~2026년 10월 일봉으로 확인해 보니(2026-10-28), 전날 밤 미국 반도체 ETF·나스닥100 ETF·S&P500 ETF 수익률은 다음 날 KODEX 200 시가가 전날 종가에서 얼마나 벌어지는지와 관계가 강했다(상관 약 0.6). 하지만 시가부터 종가까지의 수익률과는 관계가 없었다(상관 약 0). 시가에 따라 사는 규칙은 2009년 뒤 어느 기간에서나 손해였다. 그래서 미국 시세는 헤드가 상황을 판단하는 재료로만 넣고, 그것만으로 수익을 기대하지 않는다.
- 1주(5거래일) 모의 운용은 실력을 가리는 시험이 아니라, 매일 판단·정산·보고가 사고 없이 돌아가는지 보는 작동 확인이다. 5거래일 수익은 대부분 운이라 판정에 넣지 않고 보고서에만 적는다. 실력은 실전 뒤 intent의 1년 기준으로 판단한다.

## 0. 완결성 계약

- v3는 토스 캔들 조회(국내 두 종목은 v1 `fetch`와 같은 방법, 미국 네 종목은 일봉)와 Codex 호출만 한다. 주문·계좌 API는 부르지 않는다.
- Codex에는 3.2의 입력만 보낸다. 계좌 정보와 토스·Codex 인증 정보는 보내지 않는다.
- v0~v2의 명령과 동작은 그대로 둔다. 엔진과 전략 코드를 함께 쓰되, 각 버전의 acceptance가 계속 통과해야 한다.
- `uv run rt-trading v3-acceptance`는 네트워크와 인증 정보 없이 가상 시세 fixture와 가짜 Codex만으로 9절의 기준을 실행하고, 모두 통과하면 exit 0이다.
- 이 맥북의 Docker 컨테이너에서 `v3-daily`가 평일 아침마다 자동으로 돌고, 그 현황을 보기 전용 웹페이지로 확인할 수 있다.
- 실데이터로 `v3-daily`를 돌려 첫 거래일의 판단, 정산, 보고서를 한 번 만든다.
- 위 조건을 충족하면 v3는 완료다. 모의 운용 기간이 다 지나는 것과 헤드의 통과 여부는 완료 조건이 아니다. 기간이 끝나면 `v3-report`가 판정을 낸다.

| PRD 02 부하와 하루 엔진 | 부하 목록, 하루씩 이어 가는 실행, 부하 교체, 계좌별 손실 한도, 비교 계좌 | 부하와 계좌 |

| PRD 04 보고서와 판정 | 보고서, 최종 판정, `v3-report`, `v3-acceptance` | 판정과 보고서 |
| PRD 05 실행 환경과 현황 웹페이지 | Docker 컨테이너, 자동 실행, 보기 전용 현황 웹페이지, `v3-serve`, 실데이터 첫날 | 실행 환경과 현황 |

- PRD 01→05 순서로 구현한다. 각 PRD는 자기 acceptance가 통과하고 앞 PRD의 acceptance도 계속 통과하면 완료다.
- 9절의 각 항목은 정확히 한 PRD가 맡는다. PRD 05까지 완료하면 v3가 완료된다.

## 1. 목표와 비목표

### 목표

- 헤드가 매 거래일 개장 전에 부하 하나를 고르고, 이유와 다음 판단에 쓸 운용 노트를 남긴다.
- 고른 부하가 그날 실제 1분봉으로 모의 매매하고, 결과를 다음 판단의 재료로 돌려준다.
- 같은 기간 규칙 헤드 계좌와 부하별 계좌를 함께 돌려 비교한다.
- 정한 기간이 끝나면 6절 기준으로 헤드를 판정한다.
- 이 맥북의 Docker 컨테이너에서 매일 실행이 자동으로 돌고, 사람은 보기 전용 웹페이지로 현황을 확인한다.

### 비목표

- 실제 주문, 계좌·잔고 조회
- 헤드가 새 부하 코드를 만들거나 부하의 숫자를 고치는 것(부록 A)
- 뉴스·웹 검색 같은 시세 밖의 판단 재료. 나중에 넣으면 판단 방식이 바뀌므로 1주 모의 운용을 다시 한다(6절).
- 웹 관리 기능(시작·중지·재개, 전략·한도 바꾸기). 현황을 보기만 하는 웹페이지는 v3에 넣는다(8절).
- 다른 종목, 정규장 밖 거래
- v0~v2 후보 다시 백테스트

## 3. 헤드

### 3.1 모델과 호출

- trading-oracle `src/agent/codex.py`와 같은 방식으로 부른다. ChatGPT 계정 OAuth 토큰으로 `https://chatgpt.com/backend-api/codex/responses`에 `stream: true`, `store: false`로 요청하고, 응답 스트림에서 출력 텍스트만 모은다.
- 토큰은 trading-oracle과 같은 파일(`~/.trading-oracle/auth/codex.json`)을 함께 쓰고, 로그인은 trading-oracle의 `uv run main.py codex-login`으로 한다. 토큰 파일이 없으면 이유를 출력하고 그날은 판단 실패다.
- 모델은 `gpt-6-sol`로 고정하고 판단마다 기록한다. 응답에 실제 모델 이름이 오면 그것도 기록한다.
- 지시문은 저장소에 커밋한 파일 하나로 고정한다. 초안은 부록 B다.
- 한 번 부를 때 시간 제한은 120초다. HTTP 오류, 429(계정 사용량 한도), 시간 초과, 형식 오류(3.3)가 나면 1·2·4분 뒤 다시 부르고, 그 뒤로는 4분마다 판단 마감(3.4)까지 다시 부른다.

### 3.2 입력

헤드에게는 판단일 개장 전에 알 수 있는 것만 JSON 하나로 준다. 시세는 가격 자체를 보내지 않고 수익률과 비율(%)로만 보낸다.

| 항목 | 내용 |
| --- | --- |
| 날짜 | 판단일, 장 유형과 개장·마감 시각, 그달 거래일 중 앞에서·끝에서 몇째인지(휴장일 표로 센다) |
| 시세 요약 | 두 종목의 최근 20거래일 일별 수익률. KODEX 200의 최근 1·5·20·60거래일 수익률, 5·20·60·200거래일 평균 대비 위치, 최근 20거래일 변동성(연환산), 최근 60거래일 고점 대비 하락률. 모두 수정 종가로 계산한다 |
| 미국 시세 | 판단일 전 마지막 미국 장의 날짜와, 미국 반도체 ETF(SOXX)·나스닥100 ETF(QQQ)·S&P500 ETF(SPY)·마이크론(MU)의 최근 1·5·20거래일 수익률. 수정 종가로 계산하고, 미국 날짜가 판단일보다 앞선 일봉만 쓴다. 토스는 미국 지수 자체를 주지 않아서 지수를 따라가는 ETF로 대신한다 |
| 부하 | 부하마다 id, 설명, 원래 스펙의 백테스트 결과(각 SPEC 상태 줄의 숫자), 그 부하 계좌의 최근 1·5·20거래일 수익률과 지금 보유 종목 |
| 헤드 계좌 | 지금 쓰는 부하, 보유 종목, 시작 뒤 수익률, 최대 낙폭, 손실 한도 발동 상태 |
| 지난 판단 | 최근 20거래일의 판단(부하, 이유)과 그날 헤드 계좌 수익률, 판단 실패 여부 |
| 규칙 헤드 | 규칙 헤드 계좌의 시작 뒤 수익률과 최대 낙폭 |
| 운용 노트 | 직전 판단에서 헤드가 남긴 노트 |
| 정산 상태 | 정산을 마친 마지막 거래일. 정산이 밀려도(5.3) 그날까지의 값으로 입력을 만든다 |

### 3.3 출력

헤드는 다음 JSON 하나로 답한다.

```json
{"subordinate": "trend_200", "reason": "500자 이하", "notes": "2,000자 이하"}
```

- `subordinate`는 4.1 목록의 id 중 하나다.
- `notes`는 다음 판단의 운용 노트가 된다. 헤드가 판단 방식을 스스로 고치는 통로다(intent). 빈 문자열이면 노트를 비운다.
- 다른 키가 있거나, 목록 밖 id이거나, 길이를 넘거나, JSON 하나가 아니면 형식 오류다.
- 출력에 한도, 자금, 부하 목록, 모델을 바꾸는 칸은 없다. 헤드는 이것들을 바꿀 수 없다.

### 3.4 판단 마감과 실패

- 판단 마감은 판단일 개장 시각의 10분 전이다(정상일 08:50, 연초 첫 거래일·수능일 09:50). 응답을 받아 검증까지 마친 시각이 마감 전이어야 한다.
- 마감까지 올바른 응답을 받지 못했거나, 판단을 아예 하지 않은 거래일(컴퓨터가 꺼져 있던 날 등)은 그날 부하를 `cash`로 정하고 판단 실패로 센다.
- 기록한 판단은 바꾸지 않는다.

### 4.1 목록

| `hold_inverse` | 같은 방식으로 KODEX 인버스를 사서 계속 든다 | 며칠 보유 |

| `turn_of_month` | v2 SPEC 5.1 | 며칠 보유 |

- 부하의 숫자는 원래 스펙 그대로다. v3에서 바꾸지 않는다.
- 혼자서는 통과 기준을 넘지 못한 부하도 넣는다(intent). 헤드 입력에 원래 백테스트 결과를 함께 준다.
- v0 후보(종가 베팅, 갭 되돌림)는 일봉 계산만 있고 1분봉 엔진 전략이 없어 넣지 않는다.

### 4.2 하루 실행과 부하 교체

- 계좌마다 거래일마다 그날의 부하로 v2 엔진을 하루 돌리고, 마감 상태(현금, 보유, 다음 거래일로 넘어가는 주문, 손실 한도 상태)를 다음 거래일로 넘긴다.
- 전 거래일과 같은 부하면 상태를 그대로 이어 간다.
- 부하가 바뀌는 날은 개장 전에 다음을 한다.
  - 전 부하가 남긴 대기 매수는 취소한다.
  - 보유가 있으면 시가 동시호가에 판다(사유 `switch_head`). 전 부하가 남긴 대기 매도는 이 매도로 대신한다.
  - 새 부하는 그 매도 뒤의 현금 상태에서 시작한다.
- 개장 전에 낸 주문(교체 매도, 보유 부하의 첫 매수)은 그날 시가 봉에서 시가 동시호가 가격에 체결된다. 매도가 먼저, 매수가 나중이다. 손실 한도가 진입을 막고 있으면 매수는 내지 않는다.
- 부하는 그날과 그 앞의 시세만 본다(v1·v2 엔진 규칙).
- 결함일(v1 SPEC 3.4)에는 교체와 새 주문을 하지 않고 전 거래일의 부하와 상태를 다음 거래일로 넘긴다. 그날의 판단은 기록만 한다.
- 모의 운용 마지막 거래일에는 v2 SPEC 4.1처럼 새로 사지 않고, 남은 보유를 종가 동시호가에 판다.

### 4.3 비교 계좌

| 계좌 | 규칙 |
| --- | --- |
| 규칙 헤드 | 거래일마다 전 거래일 KODEX 200 추세(v2 SPEC 5.2, 평균과 같으면 아래)가 위면 `hold_kodex200`, 아니면 `cash`를 고른다. 교체 규칙은 헤드 계좌와 같다 |
| 부하 계좌 | 부하마다 하나씩, 시작일부터 그 부하만 쓴다. `hold_kodex200` 계좌가 "그냥 보유"와의 비교가 된다 |

- 모든 계좌는 같은 시세로 따로 계산하고 서로 영향을 주지 않는다.

## 5. 매일 실행

### 5.1 `v3-daily`

평일 아침에 실행한다(제안: 07:30). 같은 날 여러 번 실행해도 결과가 같다.

1. 오늘이 휴장일 표(5.2)의 휴장일이면 아무것도 하지 않는다.
2. 미국 네 종목 일봉(3.2)을 받은 뒤, 국내 시세를 v1 `fetch`와 같은 방법으로 다시 받고(전 거래일까지) v1 SPEC 3절대로 검증한다.
3. 정산하지 않은 거래일을 오래된 날부터 정산한다(5.3).
4. 오늘이 모의 운용 기간 안이면 헤드 입력을 만들고 Codex를 불러 판단을 기록한다(3절).
5. 수집, 정산, 판단 결과를 요약해 출력한다.

- 2나 3이 실패해도 4는 정산을 마친 마지막 날까지의 정보로 한다. 판단을 미루면 그날이 판단 실패가 되기 때문이다.
- 시세 받기는 판단 마감(3.4) 15분 전까지만 한다. 그때까지 끝나지 않으면 멈추고, 그 뒤에 시작하면 받지 않는다. 둘 다 2의 실패로 본다. 시세를 다 받는 데 10분쯤 걸리고, 토스가 요청을 막으면(429) 끝없이 기다릴 수 있기 때문이다.
- 한 단계라도 실패하면 이유를 출력하고 exit 1이다. 모두 성공하면 exit 0이다.
- 기간의 마지막 거래일까지 정산하면 더 판단하지 않고 기간 종료를 출력한다.

### 5.2 휴장일 표와 장 일정 표

- 모의 운용 기간의 휴장일을 KRX 공지로 확인해 저장소의 휴장일 표로 커밋한다. 오늘이 거래일인지와 그달 거래일 순서(3.2, `turn_of_month`)에 쓴다.
- 장 일정 표(`krx_sessions.csv`)에 기간 안의 연초 첫 거래일과 수능일을 넣는다.
- 정산할 때 받은 일봉의 거래일과 휴장일 표가 다르면 정산을 멈춘다.

### 5.3 정산

- 거래일 d의 정산은 d의 1분봉과 그 앞의 시세로, 그날의 부하(헤드 계좌는 d의 판단, 없으면 `cash`)에 따라 모든 계좌를 하루 돌리고 결과를 저장하는 것이다.
- 검증에 실패한 날에서 멈추고 날짜와 이유를 출력한다. 사람이 결함일 표를 고치거나 시세를 다시 받으면 다음 실행에서 이어 간다.
- 정산한 날의 시세는 사본으로 고정해, 나중에 시세를 다시 받아도 정산한 날의 결과가 바뀌지 않게 한다.

## 6. 통과 기준

기간의 5거래일을 모두 정산하면 판정한다. 헤드 계좌가 다음을 모두 만족하면 통과다.

1. 5거래일 모두 판단 마감 전에 올바른 판단을 기록했다(판단 실패 0번).
2. 최대 낙폭(v1 SPEC 6절의 식, 1분봉 평가 자산)이 20%보다 작다. 정확히 20%이면 통과하지 못한다.

- 수익, 규칙 헤드·그냥 보유와의 비교는 보고서에 적지만 판정에 넣지 않는다. 5거래일 수익은 대부분 운이다.
- 기간 중에 사람이 지시문, 헤드 입력 항목, 부하 목록이나 숫자, 모델을 바꾸면 그날부터 새 기간으로 다시 센다(intent). 헤드가 운용 노트를 고치는 것은 검증하는 판단 방식 안의 일이라 다시 세지 않는다.
- 통과해도 실계좌 운용 승인이 아니다. 실전 전환은 실전 매매 스펙에서 정한다.

## 7. 산출물

- `data/v3/paper.sqlite3`: 판단과 정산한 날. 저장 형식은 PRD에서 정한다.
- `data/v3/market.sqlite3`: 정산한 날까지의 시세 사본. 계좌별 체결과 자산열은 이 사본으로 기간 첫날부터 다시 돌려 얻는다.
- `data/v3/head/{판단일}/`: Codex에 보낸 `input.json`, 받은 원문 `response.txt`, 검증한 `decision.json`.
- `data/us.sqlite3`: 미국 네 종목 일봉. 매일 다시 받는다.
- `uv run rt-trading v3-report`를 실행할 때마다 `data/reports/v3-{실행 시각 YYYYMMDD-HHMMSS}/`에 다음을 남긴다.
  - `report.json`: 기간, 진행 상황(정산한 거래일 수/기간 거래일 수), 판단 실패 수, 계좌별 지표(v1 SPEC 7절과 같은 계산), 기간이 끝났으면 6절의 기준별 결과와 판정
  - `decisions.csv`: 판단일, 부하, 이유, 상태(`ok`, `invalid`, `failed`, `late`, `missing`), 모델, 그날 헤드 계좌 수익률
  - `trades-{계좌}.csv`: v1과 같은 열. `reason`에 `switch_head`가 더해진다
- 시세와 헤드 입력은 토스 데이터에서 나온 것이라 `data/` 아래에만 두고 커밋하지 않는다.
- 터미널에는 계좌별 최종 자산, 총수익, 최대 낙폭과 판단 실패 수, 기간이 끝났으면 판정을 표로 보여 준다.

## 9. Acceptance Criteria

`v3-acceptance`는 손으로 만든 가상 시세 fixture와, 미리 적어 둔 응답과 오류를 돌려주는 가짜 Codex만 쓴다. 각 항목은 기대값을 손으로 미리 계산해 둔 fixture로 확인한다.

- 헤드
  - 판단일과 그 뒤의 시세(미국 일봉은 미국 날짜 기준)를 바꿔도 헤드 입력이 같다. 미국 시세 수익률은 미국 거래일로 센다. 입력에 가격 자체, 계좌 번호, 토스·Codex 인증 정보가 없다.
  - 올바른 응답은 그 부하로 기록된다. 목록 밖 id, JSON이 아닌 응답, 다른 키, 길이 초과는 형식 오류다.
  - 실패 뒤 다시 부르는 간격이 3.1과 같다. 마감 전에 검증까지 마치면 정상이고, 마감 뒤에 마치거나 마감까지 실패하면 `cash`와 판단 실패로 기록된다. 정상일 08:50과 10시 개장일 09:50을 경계로 확인한다.
  - 운용 노트가 다음 판단의 입력에 들어간다.
- 부하와 계좌
  - 같은 부하가 이어지면 보유와 다음 거래일로 넘어가는 주문이 이어진다.
  - 부하가 바뀌는 날 대기 매수가 취소되고, 보유는 시가 동시호가에 `switch_head`로 팔리고, 새 부하는 현금에서 시작한다. 보유 부하의 첫 매수는 그 매도 뒤 같은 시가 동시호가 가격에 체결된다.
  - 결함일에는 교체와 새 주문이 없고 부하와 상태가 다음 거래일로 넘어간다.
  - 손실 한도가 계좌마다 따로 발동하고, 진입을 막는 동안 개장 전 매수를 내지 않는다.
  - 규칙 헤드가 전 거래일 추세로 고른다(평균과 같으면 아래).
  - 마지막 거래일에 남은 보유를 종가 동시호가에 판다.
  - 사례 안의 동시호가 체결가, 연속 매매의 한 단계 불리한 호가, 수수료, 인버스 세금, 정수 주가 손 계산과 같다.
- 매일 실행
  - 휴장일에는 아무것도 하지 않는다.
  - 정산은 오래된 날부터 하고, 검증에 실패한 날에서 멈춘다. 판단이 없는 거래일은 `cash`와 판단 실패로 정산한다.
  - 시세 받기나 정산이 실패해도 그날 판단은 하고, 입력에 정산을 마친 마지막 날이 들어간다. 시세 받기는 판단 마감 15분 전까지만 하고, 그 뒤에 시작하면 건너뛴다.
  - 같은 날 두 번 실행해도 판단과 정산이 다시 생기지 않는다.
  - 받은 일봉의 거래일과 휴장일 표가 다르면 정산을 멈춘다.
- 판정과 보고서
  - 6절의 경계: 판단 실패가 한 번이라도 있으면 불통과이고, 최대 낙폭이 정확히 20%면 불통과다. 5거래일을 모두 정산하기 전에는 판정하지 않는다.
  - `report.json`, `decisions.csv`, `trades-{계좌}.csv`의 형식과 값이 7절과 같다.
  - 같은 저장 상태로 두 번 만들면 실행 시각을 뺀 보고서 내용이 같다.
- 실행 환경과 현황
  - 평일 07:30과 08:20에 `v3-daily`와 `v3-report`를 차례로 한 번씩 실행하고(앞이 실패해도 뒤를 실행), 놓친 시각은 같은 날 09:50 전에 다시 켜지면 한 번 실행한다. 주말에는 실행하지 않는다. 실행마다 실행 기록에 시작 시각과 출력이 남는다.
  - 현황 웹페이지는 GET 요청에만 현황을 보여 주고 다른 요청은 거절한다. 판단 이유와 실행 기록 속 HTML은 글자 그대로 보인다. 가장 최근 보고서와 실행 기록의 마지막 줄들만 보여 준다. 페이지를 열어도 저장된 파일이 바뀌지 않는다.

## 10. 실데이터 실행 전 확인할 것

- **[확인 필요] 토스 약관**: 오픈 API 서비스 이용 약관 제5조 ③항은 "시세(국내주식, 해외주식)정보를 개인투자자 본인의 매매 목적에 한하여 이용하여야 하며, 제3자에게 제공하거나 배포 또는 상업적으로 활용해서는 아니 된다"이다. 공식 페이지를 열 수 없어 블로그의 인용으로 확인했고(2026-10-28), 미국 시세도 같은 조항을 따른다. 토스는 오픈 API를 LLM과 연동해 쓰도록 내세우지만, 본인 매매 목적으로 수익률·비율로 바꾼 시세 요약을 Codex(OpenAI)로 보내는 것이 "제3자 제공"인지는 약관에 없다. 토스증권 채널톡으로 확인한다. 안 되면 헤드 입력을 토스가 아닌 공개 시세로 만드는 스펙 변경이 필요하다.
- **[확인 필요] Codex 사용 조건**: ChatGPT 계정 OAuth로 Codex 백엔드를 부르는 방식은 공개된 정식 API가 아니어서, 예고 없이 바뀌거나 막힐 수 있다. 사용 조건과 계정 사용량 한도를 확인한다.
- trading-oracle에서 Codex 로그인이 되어 있고(`~/.trading-oracle/auth/codex.json`), `gpt-6-sol`로 시험 호출이 된다. Codex 백엔드는 계정에 따라 쓸 수 없는 모델이 있다(trading-oracle `AGENTS.md`).
- 휴장일 표와 장 일정 표가 모의 운용 기간을 덮는다(5.2).
- 같은 토스 키와 Codex 토큰을 쓰는 다른 프로그램(trading-oracle 등)이 자동 실행 시간(평일 07:30~09:50)에 돌지 않는다. 토스 토큰이 서로 끊기고(v1 SPEC 3.1), Codex 토큰 파일 잠금이 맥과 컨테이너 사이에는 통하지 않는다.
- 이 맥북의 공인 IP가 토스 허용 IP에 있다. 맥북은 전원을 연결해 잠들지 않게 두고, Docker Desktop은 로그인할 때 자동으로 켜지게 한다.
