# PRD: v3 PRD 05 실행 환경과 현황 웹페이지
> **상태**: 초안, 구현 전
> 상위 SPEC: [v3 SPEC](../SPEC.md)

## 의존성

- PRD 03의 `v3-daily`, 기간과 휴장일 표(`v3_daily.load_period`), `paper.sqlite3`의 `decisions`·`settled_days` 표
- PRD 04의 `v3-report`와 `report.json`
- 이 맥북의 Docker Desktop과 trading-oracle의 Codex 토큰 파일 `~/.trading-oracle/auth/codex.json`

## 문제

`v3-daily`가 평일 아침마다 빠짐없이 돌아야 판단 실패 0번 기준을 지킬 수 있다.
이 맥북을 꺼지지 않는 서버로 쓰고 Docker 컨테이너에서 돌리면, 사람이 터미널을 열지 않고는 자동 실행이 제대로 도는지 알기 어렵다.

## 목표

1. 이 맥북의 Docker 컨테이너에서 `v3-daily`와 `v3-report`를 평일 아침마다 자동 실행한다(SPEC 8절).
2. 자동 실행 상태와 모의 운용 현황을 보기만 하는 웹페이지로 보여 준다(SPEC 8절).
3. 실데이터로 첫 거래일의 판단, 정산, 보고서를 만든다(SPEC 0절).

## 범위 밖

- 판단, 계좌 실행, 정산, 보고서 자체(PRD 01~04)
- 웹에서 실행·중지·설정을 바꾸는 조작(웹 관리 스펙)
- 이 맥북 밖에서 웹페이지 열기

## 자동 실행

- `v3-serve`는 30초마다 한국 시각으로 실행 차례를 보고, 아직 실행하지 않은 차례이면 `rt-trading v3-daily`와 `rt-trading v3-report`를 차례로 실행한다. 앞 명령이 실패해도 뒤 명령을 실행한다.
- 실행 차례는 평일(월~금)의 07:30과 08:20 중 이미 지난 마지막 시각이다. 09:50(10시 개장일의 판단 마감)부터는 차례가 없다. 그래서 07:30을 놓치고 08:00에 켜지면 바로 한 번, 08:20에 또 한 번 실행하고, 09:50 이후에 켜지면 그날은 실행하지 않는다. 휴장일 판단은 `v3-daily`가 한다.
- 실행할 때마다 `data/v3/daily.log`에 `=== YYYY-MM-DD HH:MM:SS ===`(시작한 한국 시각) 한 줄을 쓰고, 두 명령의 표준 출력과 표준 오류를 이어 쓴다.
- 30초마다 하는 한 번의 확인(시계와 명령 실행 함수를 받는다)을 따로 둔다. acceptance가 가짜 시계와 가짜 명령 실행 함수를 끼운다.
- 다음 실행 예정 시각은 지금보다 뒤인 첫 평일 07:30 또는 08:20이다.
- 실행 중인지와, 켠 뒤 마지막 실행의 시작·끝 시각과 두 명령의 종료 코드를 기억해 웹페이지에 보여 준다. 다시 켜면 잊으므로 그 전의 실행은 실행 기록으로 본다.

## 컨테이너

- 이미지는 `python:3.14.2-slim`에 uv 0.13.4로 `uv sync --locked`를 해서 코드만 담고, `rt-trading v3-serve --host 0.0.0.0`을 실행한다. `.dockerignore`는 코드와 의존성 파일 밖의 모든 것을 뺀다.
- `compose.yaml`의 서비스 `v3`는 저장소의 `data/`와 `.env`(읽기 전용, 없으면 켜지지 않는다), trading-oracle과 함께 쓰는 `~/.trading-oracle/auth/`를 연결하고, 웹페이지 포트 8080을 이 맥북의 `127.0.0.1:8080`에만 연다. `restart: unless-stopped`라 Docker Desktop이 켜지면 함께 켜진다.
- `docker compose up -d --build`로 켜고 `docker compose down`으로 멈춘다. 코드나 `v3_period.json`·`krx_holidays.csv`를 바꾸면 같은 명령으로 다시 만든다. 다른 명령은 `docker compose run --rm v3 rt-trading <명령>`으로 실행한다.
- 컨테이너를 켜면 launchd 자동 실행(`com.rt-trading.v3-daily`)을 해제한다. 두 곳에서 같은 시각에 돌면 토스 토큰이 서로 끊긴다.

## 현황 웹페이지

- `v3-serve`는 `--host`(기본 `127.0.0.1`)의 8080 포트로 웹페이지를 연다. 컨테이너 안에서는 포트를 이으려고 `0.0.0.0`을 쓰고, 밖으로는 `compose.yaml`이 `127.0.0.1`에만 연다.
- `GET /`에만 UTF-8 HTML로 답한다. 다른 경로는 404, GET이 아닌 요청은 501이다. 페이지는 60초마다 스스로 새로 고치고, 접속 기록은 남기지 않는다. 페이지를 만들다 오류가 나면 500과 오류 내용을 보여 준다.
- 요청마다 저장된 파일을 읽어 아래 묶음을 위에서부터 보여 준다. 시각은 모두 한국 시각이다.
- 파일은 읽기만 한다. `paper.sqlite3`는 읽기 전용으로 열고, 파일이나 표(첫날에는 `settled_days`가 없다)가 없으면 비어 있는 것으로 본다.
- 판단 이유와 실행 기록은 Codex 응답과 프로그램 출력이므로, HTML 특수 문자를 바꿔 글자 그대로 보이게 한다.

| 묶음 | 내용 |
| --- | --- |
| 자동 실행 | `상태: 대기 중` 또는 `상태: 실행 중({차례}, {시작 시각} 시작)`. `마지막 실행: {시작 시각} 시작, {끝난 시각} 끝, v3-daily 종료 코드 {n}, v3-report 종료 코드 {n}` 또는 `마지막 실행: 없음({켠 시각}에 켠 뒤)`. `다음 실행: {YYYY-MM-DD HH:MM}`. `페이지 시각: {YYYY-MM-DD HH:MM:SS}`. 시작·끝·켠 시각은 `YYYY-MM-DD HH:MM:SS`다 |
| 기간 | `기간: {시작일} ~ {마지막 날}`, `정산 {정산한 날 수}/{기간 거래일 수} (마친 마지막 날 {날짜 또는 없음})` |
| 판단 | 기간 안의 판단 기록. 열은 `날짜`, `상태`, `부하`, `이유`이고 날짜순이다 |
| 계좌 | `data/reports/`의 `v3-*` 보고서 중 이름순으로 가장 뒤의 것. `보고서: {디렉터리 이름}`과, 계좌마다 `계좌`, `최종 자산`(`499,632원`), `총수익`(부호와 소수 둘째 자리 `-0.07%`), `최대 낙폭`(소수 둘째 자리 `0.12%`), `거래 수`. 그 아래 `판정: 기간 중`(`verdict`가 `null`) 또는 `v3-report` 터미널 요약과 같은 판정 줄. 보고서가 없으면 `보고서 없음` |
| 최근 실행 기록 | `data/v3/daily.log`의 마지막 40줄. 없으면 `기록 없음` |

## 가상 fixture

- 실행 차례 사례마다 한국 시각, 기대하는 차례(`YYYY-MM-DD HH:MM`, 없으면 `null`), 다음 실행 예정 시각을 적는다. 07:29:59, 07:30, 08:19:59, 08:20, 09:49:59, 09:50, 금요일 08:20, 토·일요일을 넣는다.
- 자동 실행 사례는 한 번의 확인을 시각 순서대로 부르고, 시각마다 실행할 명령과 끝난 뒤의 실행 기록·마지막 실행 상태를 적는다. 가짜 명령 실행 함수는 `{명령} 출력` 한 줄을 쓰고, `v3-daily`는 1, `v3-report`는 0을 돌려준다.
- 현황 페이지 사례는 임시 디렉터리에 기간 설정과 휴장일 표, 판단 행과 정산한 날을 넣은 `paper.sqlite3`, 이름이 다른 보고서 두 개, 45줄짜리 실행 기록을 만들고, 자동 실행 상태와 지금 시각을 준다. 판단 이유 하나에 `<script>`를 넣는다. 첫날처럼 `settled_days` 표가 없는 `paper.sqlite3`로도 페이지를 만든다.
- 임시 포트에서 웹페이지를 띄워 요청하고, 페이지에 있어야 할 글자와 없어야 할 글자를 손으로 적어 비교한다.

## 필수 Acceptance

SPEC 9절의 "실행 환경과 현황" 항목을 맡는다.

- 실행 차례가 평일 07:30·08:20 경계와 09:50 마감, 주말에 맞고, 다음 실행 예정 시각이 맞다(금요일 08:20 뒤에는 다음 월요일 07:30). 차례마다 `v3-daily`와 `v3-report`를 차례로 한 번씩 실행하고(`v3-daily`가 실패해도), 같은 차례에는 다시 실행하지 않는다. 실행 기록에 시작 시각 줄과 두 명령의 출력이, 마지막 실행 상태에 종료 코드가 남는다.
- `GET /`의 페이지에 자동 실행 상태, 기간과 정산 진행, 판단, 최신 보고서의 계좌 지표와 판정, 실행 기록 마지막 40줄이 나온다. 옛 보고서의 값과 마지막 40줄 앞의 기록은 나오지 않고, 이유 속 `<script>`는 글자로 보인다. 다른 경로는 404, POST는 501이다. `settled_days` 표가 없는 첫날 `paper.sqlite3`로 만들면 `정산 0/5 (마친 마지막 날 없음)`이 나오고 파일이 바뀌지 않는다.

## 완료 조건 (v3 완료)

- `uv run rt-trading v3-acceptance`가 exit 0이다.
- `cli.py`를 바꾸므로 `uv run rt-trading acceptance`, `uv run rt-trading v0-acceptance`, `uv run rt-trading v2-acceptance`로 기존 명령이 그대로인지 확인한다.
- 이 맥북에서 `docker compose up -d --build`로 컨테이너를 켜고 `http://127.0.0.1:8080`에서 현황이 보이는지 확인한다. launchd 자동 실행을 해제한다.
- SPEC 10절을 확인한 뒤 실데이터로 다음을 한다.
  1. 기간 첫날 아침 자동 실행으로 첫 판단을 기록한다.
  2. 다음 거래일 아침 자동 실행으로 첫날을 정산하고 보고서를 만든다.
  3. 웹페이지에서 판단, 정산 진행, 계좌 지표를 확인한다.
- SPEC과 모든 PRD의 상태를 "구현 완료"로 바꾼다. 모의 운용 기간이 다 지나는 것과 판정 결과는 완료 조건이 아니다.
