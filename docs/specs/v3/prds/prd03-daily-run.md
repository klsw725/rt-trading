# PRD: v3 PRD 03 매일 실행
> **상태**: 초안, 구현 전
> 상위 SPEC: [v3 SPEC](../SPEC.md)

## 의존성

- PRD 01의 헤드 입력 만들기, 판단, `decisions` 표
- PRD 02의 계좌 실행(`v3_paper.simulate`)과 계좌 순서
- v1 시세 받기(`rt-trading fetch` 명령), 데이터 검증(`market_data.load`), 저장 형식(`store`), 가상 시세 fixture 생성기(`fixtures.build`)

## 문제

매일 아침 시세를 받아 밀린 날을 정산하고, 오늘 판단을 해야 한다.
시세를 다시 받아도 정산한 날의 결과는 바뀌지 않아야 하고, 정산이 막혀도 판단은 해야 한다. 판단을 미루면 그날이 판단 실패가 되기 때문이다.

## 목표

1. 휴장일 표와 기간 설정을 두고, 거래일 달력과 기간을 정한다(SPEC 2절·5.2).
2. 정산한 날의 시세를 고정해 두는 시세 사본을 만든다(SPEC 5.3).
3. 밀린 날을 정산하고, 판단이 없는 거래일을 `missing`으로 기록한다(SPEC 5.3).
4. 헤드 입력에 넣을 계좌 요약을 만든다(SPEC 3.2).
5. `v3-daily`를 만든다(SPEC 5.1).

## 범위 밖

- 보고서와 판정(PRD 04), 자동 실행(PRD 05)

## 달력과 기간

- `krx_holidays.csv`에는 주말이 아닌 휴장일만 KRX 공지로 확인해 적는다. 기간 시작일이 속한 달부터 기간 마지막 날의 다음 달 말까지 덮어야 한다(`turn_of_month`가 다음 달 셋째 거래일을 찾는다).
- 거래일 달력은 시작일 전에는 시세의 거래일이고, 시작일부터는 주말과 휴장일을 뺀 날이다. PRD 02의 `calendar`와 헤드 입력의 그달 거래일 목록에 쓴다.
- 기간은 시작일부터 달력의 5거래일이고, 다섯째 날이 `final_day`다.
- 시작일은 사용자가 `v3_period.json`에 적는다. 파일이 없거나, 시작일이 주말이거나 휴장일이면 `V3_PERIOD_INVALID`로 아무것도 하지 않고 exit 1이다.

## 시세 사본

- 정산한 날의 시세는 `data/v3/market.sqlite3`에 따로 둔다. 표와 열은 v1 저장 형식(`store`)과 같다.
- 거래일 x를 사본에 넣을 때는 원본 `data/market.sqlite3`에서 x의 두 종목 1분봉·일봉 행과, 원본의 가장 늦은 `fetch_runs` 네 행을 넣는다. 사본에 이미 있는 행은 넣지도 바꾸지도 않는다.
- 사본이 없으면 x를 넣기 전에 원본에서 시작일 전의 모든 행을 넣는다. 노이즈 영역 돌파의 14거래일, 추세의 200거래일, 기준가 계산이 이 행을 쓴다.
- 계좌 결과는 사본을 `market_data.load`로 읽어 PRD 02 계좌 실행으로 기간 첫날부터 다시 돌려 얻는다. 사본에 넣은 행은 바뀌지 않으므로, 원본을 다시 받아도 정산한 날의 결과는 그대로다.

## 정산

- 정산할 날은 기간의 거래일 중 오늘보다 앞서고 아직 정산하지 않은 날이다. 오래된 날부터 한다.
- 먼저 원본을 `market_data.load`로 검증한다. 어긴 것이 있으면 그대로 출력하고, 어긴 것 중 가장 이른 날짜보다 앞선 날만 정산한다. 날짜가 없는 위반(`V1_DATA_MISSING` 등)이면 정산하지 않는다.
- 원본의 시작일 뒤 거래일이 달력의 같은 범위(시작일부터 원본의 마지막 날까지)와 다르면 `V3_CALENDAR_MISMATCH`와 다른 날짜를 출력하고 정산하지 않는다.
- 날마다 다음을 한다.
  1. 원본에 그날이 없으면 `V3_DATA_NOT_READY`를 출력하고 멈춘다.
  2. 사본을 임시 파일로 복사해 그날 시세를 넣고 `market_data.load`로 검증한다. 어긴 것이 있으면 출력하고 임시 파일을 지운 뒤 멈춘다. 통과하면 임시 파일로 사본을 바꾼다. 사본에는 검증을 통과한 날만 들어간다.
  3. 그날 판단 행이 없으면 `missing` 행을 넣는다. 부하는 `cash`, 시도 횟수는 0, 나머지 문자열 열은 빈 문자열이다.
  4. `data/v3/paper.sqlite3`의 `settled_days` 표에 그날과 정산한 시각을 넣는다.
- `settled_days`의 열은 `date`(기본 키), `settled_at`(초까지 적은 RFC 3339 한국 시각)이고 둘 다 `TEXT NOT NULL`이다.
- 2와 3·4 사이에 멈춰 사본에만 그날 행이 남아도, 다음 실행에서 그날을 다시 정산하면 사본에는 더 넣지 않고 3·4만 한다.

## 계좌 요약

판단일 d의 헤드 입력(PRD 01)에 넘길 값이다. 수는 PRD 01과 같이 `%` 단위로 소수 둘째 자리에서 반올림(`ROUND_HALF_UP`)한다.

- 정산한 날이 있으면 사본으로 열 계좌를 정산한 마지막 날까지 돌린다. 정산한 날이 없으면 모든 계좌가 시작 상태(현금 500,000원, 보유 없음, 수익률·낙폭 0, 한도 없음)다.
- 계좌의 마감 자산을 정산한 날 순서로 `C_1 … C_n`, 시작 자금을 `C_0 = 500,000`이라 한다.

| 값 | 계산 |
| --- | --- |
| 부하 계좌의 `recent_returns_pct` | k = 1, 5, 20마다 `C_n ÷ C_(n−k) − 1`. `n − k`가 0보다 작으면 `C_0`을 쓴다. 키는 `"1d"`, `"5d"`, `"20d"` |
| `holding` | 마지막 정산일 마감 때 들고 있는 종목 코드. 없으면 `null` |
| `head_account.subordinate` | 마지막 정산일의 e(PRD 02). 정산한 날이 없으면 `null` |
| `return_since_start_pct` | `C_n ÷ C_0 − 1` |
| `max_drawdown_pct` | `C_0`과 1분봉 자산열 전체의 최대 낙폭(v1 SPEC 6절의 식) |
| `head_account.limits` | `{"weekly", "cumulative"}`. d에 진입을 막고 있는 한도다. `weekly`는 d와 같은 ISO 주에 한 주 한도가 발동했는지, `cumulative`는 누적 한도가 발동한 적이 있는지 |
| 날마다 `head_return_pct` | 헤드 계좌의 `C_t ÷ C_(t−1) − 1` |
| `settled_through` | 마지막 정산일. 없으면 `null` |
| 그달 거래일 목록 | 달력에서 d가 속한 달의 거래일 |

## `v3-daily`

SPEC 5.1의 순서로 한다.

1. 기간 설정과 휴장일 표를 읽는다. 오늘이 주말이거나 휴장일이면 `휴장일`을 출력하고 exit 0이다. 시세를 받지 않고, Codex를 부르지 않고, 파일을 만들거나 바꾸지 않는다.
2. 시세를 받는다. 판단 마감(PRD 01, 개장 10분 전) 15분 전까지 남은 초를 시세 받기 함수에 주고, 이미 그 시각이 지났으면 받지 않고 `V3_FETCH_SKIPPED: 판단 마감 15분 전이 지나 시세를 받지 않았다`를 출력한다. 받지 않았거나 실패하면 시세 받기 실패(`V3_FETCH_FAILED`)이고, 그 출력을 그대로 두고 다음 단계로 간다.
   - 실제 시세 받기 함수는 v1 `fetch` 명령(`rt-trading fetch`)을 따로 실행하고, 남은 초 안에 끝나지 않으면 멈추고 `V3_FETCH_TIMEOUT: 판단 마감 15분 전까지 시세를 다 받지 못해 멈췄다`를 출력한다. v1 `fetch`는 다 받은 뒤 한 트랜잭션으로 저장하므로, 멈춰도 원본은 그대로이거나 SQLite가 되돌린다.
3. 위 정산을 한다.
4. 오늘이 기간의 거래일이면 판단한다.
   - 오늘 판단 행이 이미 있으면 다시 부르지 않는다.
   - 계좌 요약을 만들어 PRD 01의 판단을 부른다. 마감이 지났으면 PRD 01이 부르지 않고, 그날은 다음 정산 때 `missing`이 된다.
5. 기간의 마지막 거래일까지 정산했으면 `기간 종료`를 출력한다. 오늘이 시작일 전이면 `기간 전`을 출력한다.
6. 받은 시세 기간, 정산한 날, 오늘 판단(상태와 부하), 실패한 단계의 코드를 출력한다.

- 2·3·4 중 하나라도 실패하면 exit 1이고, 아니면 exit 0이다.
- 시세 받기 함수(남은 초를 받는다), Codex 클라이언트, 시계, 기다리기, 파일 위치(원본·사본·`paper.sqlite3`·헤드 기록 폴더), 기간 설정과 휴장일 표는 인자로 받는다. acceptance가 바꿔 끼운다.

## 가상 fixture

- 원본 시세는 실행마다 그날 아침까지 받을 수 있는 날을 담은 `fixtures.build` spec으로 만든다. 가짜 시세 받기 함수가 원본 파일을 그 spec으로 바꾸고, 실패 사례에서는 원본을 그대로 두고 1을 돌려준다. 받은 남은 초를 기록하고, 시간 초과 사례에서는 원본을 그대로 둔 채 가짜 시계를 남은 초만큼 움직이고 1을 돌려준다.
- 시간 제한 사례는 시작일 전까지의 시세를 이미 받아 둔 원본에서 시작하는 실행 순서를 따로 둔다.
- Codex는 PRD 01과 같은 가짜 Codex를 쓰고, 부른 횟수를 센다.
- 휴장일 표와 기간 시작일은 fixture에 적어 인자로 넘긴다. 결함일은 실제 결함일 표의 날을 쓴다.
- 사례마다 실행 순서(날짜·시각), 그때의 원본 spec과 Codex 응답, 기대(정산한 날, `decisions` 행, 출력에 나올 코드, exit, Codex 호출 수, 파일 변경 여부)를 적는다.

## 필수 Acceptance

SPEC 9절의 "매일 실행" 항목을 맡는다.

- 휴장일과 주말에는 시세 받기와 Codex 호출이 없고, 파일이 생기거나 바뀌지 않으며, exit 0이다.
- 정산은 오래된 날부터 하고, 검증에 실패한 날에서 멈춘다. 판단이 없는 거래일은 `missing`과 `cash`로 정산한다.
- 시세 받기나 정산이 실패해도 그날 판단은 하고, 헤드 입력의 `settled_through`가 정산을 마친 마지막 날이다.
- 시세 받기에는 판단 마감 15분 전까지 남은 초(정상일 07:30 시작이면 3,900초)를 주고, 그때까지 끝나지 않아도 판단한다. 그 시각이 지나 시작하면 시세를 받지 않고 판단한다.
- 같은 날 두 번 실행하면 두 번째 실행에서 Codex 호출이 없고, 판단 행과 정산한 날이 더 생기지 않는다.
- 원본의 거래일과 휴장일 표로 만든 달력이 다르면 `V3_CALENDAR_MISMATCH`로 정산하지 않는다.

## 완료 조건

- `uv run rt-trading v3-acceptance --prd 03`과 `--prd 01`, `--prd 02`가 exit 0이다.
- `cli.py`를 바꾸므로 `uv run rt-trading acceptance`, `uv run rt-trading v0-acceptance`, `uv run rt-trading v2-acceptance`로 기존 명령이 그대로인지 확인한다.
