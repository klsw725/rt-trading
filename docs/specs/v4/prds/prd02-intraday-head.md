# PRD: v4 PRD 02 하루 여러 번 판단하는 헤드
> **상태**: 초안, 구현 전
> 상위 SPEC: [v4 SPEC](../SPEC.md)

## 의존성

- v3 헤드(`v3_head`)의 시세 요약·미국 시세 요약 계산, 응답 검증, 기록 방식. v3 동작은 바꾸지 않는다. 함께 쓰려고 함수를 나누거나 선택 인자를 더하면 v3 acceptance가 계속 통과해야 한다.
- Codex 클라이언트(`codex.ask`, `codex.credentials`, `codex.MODEL`)
- v1 장 일정 표(`sessions`), 1분봉 표기(`market_data.Bar`, 봉이 끝나는 시각), 시가 봉(`market_data.open_bar`)
- PRD 01의 뉴스 값

## 문제

v3 헤드는 하루 한 번, 개장 전에만 판단한다. v4 헤드는 하루 여러 번 판단하고, 장중에는 그날의 시세와 뉴스를 본다.
실패하면 지금 부하를 그대로 두어야 하고, 장중 교체는 하루 2번까지만 실행해야 한다.
판단할 때 계산한 지금 부하와, 다음 날 정산할 때 쓰는 부하가 어긋나면 안 된다.

## 목표

1. 그날의 판단 차례와 마감을 정한다(SPEC 3.1).
2. 판단 기록으로 시각마다의 계획 부하를 계산한다. 이 PRD의 지금 부하·남은 교체 횟수와 PRD 03의 헤드 계좌가 같은 계산을 쓴다.
3. v4 헤드 입력을 만든다. 오늘 시세 요약은 호출하는 쪽이 넘긴 당일 1분봉으로 계산한다(SPEC 3.2).
4. 응답을 검증하고, 다시 부르기·마감·교체 한도를 지켜 판단을 기록한다(SPEC 3.3·3.4).
5. v4 지시문과 부하 설명 표를 둔다.

## 범위 밖

- 당일 1분봉과 뉴스 받기, 받기 마감, 계좌 요약, `v4-daily`·`v4-decide`(PRD 04)
- 뉴스 고르기와 다듬기(PRD 01)
- 엔진과 계좌 실행, 결함일 처리(PRD 03)

## 판단 차례

판단일 d의 장 일정(v1 장 일정 표)의 개장 o와 마감 c로 정한다. 시각은 한국 시각이다.

| 종류 | 차례 | 마감 | 교체 시각 |
| --- | --- | --- | --- |
| `pre_open` | o − 10분 | o − 10분 | 개장(시가 동시호가) |
| `intraday` | o + 60분부터 c − 90분까지 정각마다 | 차례 + 5분 | 차례 + 5분 |
| `pre_close` | c − 20분 | 차례 + 5분 | 차례 + 5분 |

- 차례는 `HH:MM`이다. `pre_open`은 마감 시각을 차례 이름으로 쓴다. 판단 시각 T는 `pre_open`이면 입력을 만드는 시각이고, 그 밖에는 차례다.
- 교체 시각 t는 엔진에서 t에 끝나는 봉이 끝날 때 교체 주문을 내 다음 봉 시가에 체결한다는 뜻이다(PRD 03).
- 정상일(09:00~15:30)은 `08:50`, `10:00`, `11:00`, `12:00`, `13:00`, `14:00`, `15:10`이다. 연초 첫 거래일(10:00~15:30)은 `09:50`, `11:00`, `12:00`, `13:00`, `14:00`, `15:10`이다. 수능일(10:00~16:30)은 `09:50`, `11:00`, `12:00`, `13:00`, `14:00`, `15:00`, `16:10`이다.

## 계획 부하

기간의 거래일 목록과 판단 기록으로, 날마다 시작 부하와 장중 교체 목록 `(시작 부하, [(교체 시각, 부하), …])`를 정한다. 이것이 계획 부하 P다.

- d의 시작 부하는 d의 `pre_open` 판단 상태가 `ok`면 그 부하다. 아니면 d의 전 거래일 마감 때의 P이고, 기간 첫날이면 `cash`다.
- d의 `intraday`·`pre_close` 판단을 차례 순서로 본다. 상태가 `ok`이고 부하가 그때의 P와 다르면 (차례 + 5분, 그 부하)를 교체 목록에 더하고 P를 바꾼다.
- 상태가 `ok`가 아닌 판단(`capped` 포함)과, 그때의 P와 같은 부하를 고른 `ok` 판단은 P를 바꾸지 않는다.
- 결함일인지는 보지 않는다. 판단할 때는 그날이 결함일인지 모르기 때문이다. 결함일의 처리는 PRD 03이 한다.
- 판단일 d의 차례 s에서 지금 부하는 d의 시작 부하에 s보다 앞선 차례의 교체를 반영한 P이고, 남은 교체 횟수는 2에서 그 교체 수를 뺀 값이다.

| `today_market` | `pre_open`이면 `null`이다. 그 밖에는 아래 오늘 시세 요약이고, 당일 1분봉을 받지 못했으면 `null`이다 |

| `head_account`, `rule_head` | v3 PRD 01과 같다. 호출하는 쪽이 넘긴다 |

| `settled_through` | v3 PRD 01과 같다 |

- 판단 기록의 순서는 (날짜, 차례)다. 차례는 두 자리 시각이라 글자 순서가 곧 시각 순서다.
- 입력에는 가격 자체, 계좌 번호, 토스·네이버·Codex 인증 정보가 들어갈 자리가 없다.

### 오늘 시세 요약

호출하는 쪽이 넘긴 d의 1분봉 중 시각이 d의 장 일정 봉 시각이고 T보다 늦지 않은 봉만 쓴다. `today_market`은 `{"kodex200": …, "inverse": …}`이고, 종목마다 쓸 봉이 없으면 그 종목은 `null`, 두 종목 모두 없으면 `today_market`이 `null`이다. 쓴 마지막 봉을 L이라 한다.

| 키 | 계산 |
| --- | --- |
| `data_through` | L의 시각 |
| `vs_prev_close_pct` | L 종가 ÷ d보다 앞선 마지막 날 일봉의 원가격 종가 − 1. 분배락일에는 분배금만큼 낮게 나온다 |
| `vs_open_pct` | L 종가 ÷ 시가 봉(쓴 봉 중 처음 거래량이 있는 봉)의 시가 − 1. 시가 봉이 없으면 `null` |
| `range_position_pct` | (L 종가 − 최저가) ÷ (최고가 − 최저가). 최고가·최저가는 쓴 봉 중 거래량이 있는 봉의 고가·저가에서 정한다. 둘이 같거나 그런 봉이 없으면 `null` |
| `last_30m_pct` | L 종가 ÷ L보다 30분 앞 시각 봉의 종가 − 1. 그 봉이 없으면 `null` |
| `returns_30m_pct` | 개장부터 30분씩 끊은 구간의 수익률, 오래된 것부터. k번째 구간의 끝 시각은 o + 30k분이고, 끝 시각이 L의 시각보다 늦지 않은 구간만 넣는다. 수익률은 끝 시각 봉의 종가 ÷ 앞 구간 끝 시각 봉의 종가 − 1이고, 첫 구간은 시가 봉의 시가로 나눈다. 필요한 봉이 없으면 그 구간은 `null` |

## 지시문

`v4_head_prompt.txt`는 SPEC 부록 B의 코드 블록 안 글 그대로다.

## Codex 호출과 다시 부르기

- 호출은 v3 PRD 01과 같다(`codex.ask`, 한 번에 120초). 지시문만 `v4_head_prompt.txt`이고, 사용자 입력 텍스트는 헤드 입력을 키 순서 그대로, 한글 그대로 쓴 JSON 문자열이다.
- `pre_open`은 v3 PRD 01과 같이 실패하면 1분, 2분, 4분을 기다린 뒤 다시 부르고, 그 뒤로는 4분마다 다시 부른다.
- `intraday`와 `pre_close`는 실패하면 15초를 기다린 뒤 다시 부르고, 그 뒤로도 15초마다 다시 부른다.
- 기다리는 시간은 앞 호출이 끝난 때부터 센다. 다음 호출을 시작할 시각이 마감과 같거나 늦으면 부르지 않는다. 토큰이 없으면(`V3_CODEX_TOKEN_MISSING`) 다시 부르지 않는다.
- 첫 호출을 시작할 시각이 이미 마감과 같거나 늦으면 부르지도 기록하지도 않는다. 그 차례는 PRD 04가 정산할 때 `missing`으로 남긴다.
- 시계와 기다리기는 함수로 받는다.

## 응답 검증

- v3 PRD 01과 같다. 부하 id는 `v4_subordinates.json`의 id다. 형식 오류 코드는 v3와 같은 `V3_HEAD_RESPONSE_INVALID`다.

## 상태와 교체 한도

| 상태 | 뜻 |
| --- | --- |
| `ok` | 마감보다 이른 시각에 응답을 받아 검증까지 마쳤다 |
| `capped` | `ok`와 같이 마쳤지만 `intraday`·`pre_close` 판단이 지금 부하와 다른 부하를 골랐고, 남은 교체 횟수가 0이다. 실행하지 않는다 |
| `late` | 검증은 통과했지만 마친 시각이 마감과 같거나 늦다 |
| `invalid` | 마지막 시도가 형식 오류로 끝났다 |
| `failed` | 마지막 시도가 호출 오류로 끝났다 |
| `missing` | 그 차례에 판단을 하지 않았다. PRD 04가 정산할 때 넣는다 |

- `ok`, `capped`, `late`의 `subordinate`는 답한 부하다. `ok`와 `capped`의 `reason`, `notes`는 답한 값이다. 나머지 경우 이 세 열은 빈 문자열이다.
- 판단 실패는 `late`, `invalid`, `failed`, `missing`이다. `ok`가 아닌 판단은 계획 부하를 바꾸지 않으므로, 실패하면 지금 부하가 이어진다.

## 판단 기록

`data/v4/paper.sqlite3`의 `decisions` 표에 판단 차례마다 한 행을 넣는다. 파이썬 기본 `sqlite3`를 쓰고, 표가 없으면 만든다.

| 열 | 내용 |
| --- | --- |
| `date`, `slot` | 판단일과 차례. 둘이 기본 키다 |
| `kind` | `pre_open`, `intraday`, `pre_close` |
| `status`, `subordinate`, `reason`, `notes` | 위와 같다 |
| `model`, `reported_model`, `attempts`, `error`, `started_at`, `finished_at` | v3 PRD 01과 같다 |

- 모든 열은 `NOT NULL`이고, `attempts`만 `INTEGER`, 나머지는 `TEXT`로 선언한다.
- `data/v4/head/{d}/{차례 HHMM}/`에 호출 전에 `input.json`을 쓰고, 끝나면 마지막 응답 원문 `response.txt`(응답이 없었으면 만들지 않는다)와 기록한 행과 같은 내용의 `decision.json`을 쓴다. JSON 형식은 v3와 같다.
- (d, s) 행이 이미 있으면 Codex를 부르지 않고 그 행을 돌려준다. 기록한 판단은 바꾸지 않는다.

## 가상 fixture

- 일봉과 미국 일봉은 v3 PRD 01의 spec 방법으로 임시 SQLite 파일을 만든다. 미국 일봉 사례 하나는 한국만 쉬는 날을 넣어, 미국 거래일로 센 수익률을 확인한다.
- 당일 1분봉은 종목마다 바꿀 봉만 적고, 나머지 장 일정 봉은 직전 봉 종가로 채운 목록을 acceptance가 만든다. T 뒤의 봉, 거래량 0인 개장 전 봉, 장 일정 밖 시각의 봉을 넣는다.
- 오늘 시세 사례는 정상일 T = 11:00로 하고, 다섯 값이 모두 0이 아니고 30분 구간이 네 개가 되게 가격을 둔다. 한 종목만 봉이 없는 사례와 두 종목 모두 없는 사례를 함께 둔다.
- 계획 부하 사례는 판단 기록을 직접 적는다. 같은 날 교체 두 번, 같은 부하를 고른 `ok`, 실패, `capped`, 다음 날 `pre_open` 실패, 기간 첫날 `pre_open` 실패를 넣는다.
- 가짜 Codex와 가짜 토큰은 v3 PRD 01과 같은 방법(`httpx.MockTransport`, 임시 토큰 파일)이다. 시계는 가짜 시계이고, 기다린 시간을 기록한다.
- 계좌 요약, 그달 거래일 목록, 뉴스 값은 fixture에 직접 적는다.
- 사례마다 기대 입력과 기록 행을 손으로 계산해 함께 적고 그대로 비교한다.

## 필수 Acceptance

SPEC 9절의 "헤드" 항목을 맡는다.

- T 뒤의 당일 1분봉과 기사, 판단일과 그 뒤의 일봉(미국 일봉 포함)을 바꿔도 입력이 손으로 계산한 기대 입력과 같다. 오늘 시세의 다섯 값과 30분 구간이 손 계산과 같고, 당일 1분봉이 없으면 그 종목이나 `today_market`이 `null`이다. 가짜 토큰과 계좌 id 문자열이 입력, 요청 본문, 기록, 출력 어디에도 없고, 입력에 가격 자체가 없다.
- 판단 차례와 마감이 정상일(2026-01-05), 연초 첫 거래일(2026-01-02), 수능일(2025-11-13)에 위 표와 같다. 세 날 모두 마지막 교체 시각(마감 전 차례 + 5분)이 종가 동시호가 접수 구간(마감 9분 전부터)보다 이르다.
- 장중 판단은 실패하면 15초마다 다시 부른다. 마감(차례 + 5분)보다 일찍 검증까지 마치면 `ok`, 마감과 같거나 늦으면 `late`, 마감까지 형식 오류나 호출 오류로 끝나면 `invalid`나 `failed`이고 계획 부하가 바뀌지 않는다. 첫 호출을 시작할 시각이 마감이면 부르지도 기록하지도 않는다. 개장 전 판단은 1·2·4분 간격이고, 2026-01-05 08:50과 2026-01-02 09:50이 마감이다(v3에서 옮긴 사례).
- 목록 밖 id, 다른 키, 501자 `reason`은 형식 오류이고, `overnight`을 고른 응답은 통과한다(v3에서 옮긴 사례).
- 같은 날 장중 교체 두 번 뒤에 다른 부하를 고르면 `capped`로 기록되고 계획 부하가 바뀌지 않는다. 같은 부하를 고른 `ok`와 개장 전 교체는 교체 수에 넣지 않는다. 입력의 `switches_left`가 2, 1, 0으로 줄고 `current`가 그때의 계획 부하다.
- `pre_open`이 `ok`가 아닌 날은 전 거래일 마감 때의 계획 부하로 시작하고, 기간 첫날은 `cash`로 시작한다.
- `ok`와 `capped` 판단의 `notes`가 같은 날 다음 판단과 다음 거래일 첫 판단의 입력에 들어간다. 사이에 실패한 판단이 있어도 마지막 `ok`·`capped` 판단의 노트가 들어간다.

## 완료 조건

- `uv run rt-trading v4-acceptance --prd 02`와 `--prd 01`이 exit 0이다.
- v3 헤드 코드를 나누거나 인자를 더했으면 `uv run rt-trading v3-acceptance`가 exit 0이다.
