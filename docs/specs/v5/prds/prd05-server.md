# PRD: v5 PRD 05 서버
> **상태**: 승인(2026-11-04, 사용자가 정한 대로 오라클 검토 통과로 승인)
> 상위 SPEC: [v5 SPEC](../SPEC.md)

## 의존성

- v4 자동 실행·현황 웹페이지(`v4_serve`의 `due`·`tick` 방식, `page`, `v3_serve.server`)와 web 스펙의 모양(`web`)
- PRD 02의 v5 기간, PRD 03의 실행기(`v5-live`)·저장소(`v5_book`)·차례(`turns`), PRD 04의 `v5-daily`·`v5-decide`·`v5-report`
- 서버 `ka1rm31`의 Docker와 `compose.yaml`, 저장소 루트의 `.env`, Codex 토큰 파일

## 문제

v4 자동 실행은 명령을 한 번에 하나씩 차례로 돌린다. v5는 판단 명령과 따로, 장중 내내 실행기를 함께 돌려야 하고, 실행기가 멈추면 다시 켜야 한다.
사용자는 실계좌 상태(멈췄는지, 무엇을 들고 있는지, 수익, 오늘 주문)를 한 페이지에서 봐야 한다.

## 목표

1. `v5-serve`가 아침·판단 차례를 v4처럼 돌리고, 실행기를 따로 함께 돌린다.
2. 현황 페이지 맨 위에 실계좌 묶음을 더한다(SPEC 8절).
3. v4에서 v5로 넘어오고, 연습 운용과 실주문 점검을 한다(SPEC 0절, 부록 A).

## 범위 밖

- 실행기 안의 동작(PRD 03), 판단·정산·보고서 내용(PRD 04)
- 실주문 켜기와 수량 늘리기. 사용자가 SPEC 6절대로 정한다.

## 자동 실행

- 아침 차례와 판단 차례, 시간 제한, 실행 기록은 v4 PRD 05와 같다. 명령은 `v5-daily`·`v5-report`와 `v5-decide --at s`이고, 기록은 `data/v5/run.log`다. 판단 차례는 v5 기간(PRD 02, 확인할 때마다 그날로 다시 계산)의 거래일에 한다.
- 실행기 돌보기는 판단 명령과 따로 돈다(스레드 하나). v5 기간(시작일부터)의 거래일 o − 15분부터, 그날 `end`를 마쳤다는 기록(`live.sqlite3`의 `days`)이 생길 때까지 `rt-trading v5-live`가 돌고 있지 않으면 켠다. 끝나면 30초 뒤 다시 켠다. c + 10분이 지나 켜진 실행기는 `end`만 하고 끝난다(PRD 03). 그날 자정이 지나면 그날 실행기를 켜지 않는다. 출력은 `data/v5/live.log`에 이어 쓴다. 휴장일에는 켜지 않는다.

## 현황 웹페이지

- v4 페이지(web 스펙의 모양)와 같은 묶음에 실계좌 묶음을 맨 위에 더한다. 제목은 `rt-trading v5 현황`이다. 판단 지도는 v5 기간의 오늘까지 최근 5거래일이다. 기간 칸은 시작일과 정산한 날 수만 보인다. 판단 칸의 통과 기준 줄은 없다. 헤드 계좌 칸과 계좌 표는 `data/reports/`의 `v5-*` 중 이름순으로 가장 뒤의 보고서(`report.json`의 `accounts`, `trades-head.csv`)를 web 스펙대로 읽는다.
- 실계좌 묶음은 `live.sqlite3`를 읽기 전용으로 열어 만든다. 봇 자산과 실계좌 상태는 가장 최근 `turns` 기록의 값이다.

| 칸 | 보이는 것 |
| --- | --- |
| 실행 | 그날 방식(`연습 운용` 또는 `실주문`, `days`), 정지 상태(`정지 없음` 또는 풀리지 않은 정지마다 종류·방식·이유·시각, `수동 확인 필요`는 토스 앱에서 정리한 뒤 `v5-resume --new-ledger`를 하라는 안내와 함께), 마지막 차례의 시각과 한 일 |
| 봇 자산 | 그날 방식의 장부(연습 운용이면 연습 장부, 실주문이면 실장부. 그 장부가 없을 때만 `장부 없음`)의 `보유: {종목 이름} {수량}주` 또는 `보유: 현금`, 봇 현금, 봇 자산과 `수익 {+N}원 ({+x.xx%})`(가장 최근 차례의 1분봉 종가 기준, 차례마다 바뀐다), 그 차례의 두 종목 가격. 연습 장부면 `연습` 표시를 붙인다 |
| 실계좌 대조 | 마지막으로 본 차례의 실계좌 두 종목 수량과 장부가 같은지(`장부와 같음` 또는 `장부와 다름`과 두 수량) |
| 한도 | 오늘 하루 한도·이번 주 한 주 한도 발동 여부(`latches`), 누적 한도 정지 여부, 거부 센 것 |
| 오늘 | 차례마다 시각, 목표 또는 정하지 않은 이유, 한 일(최근 것부터 20개) |
| 오늘 주문 | 오늘 봇 주문(실·연습·점검)의 시각, 구분, 종목, 방향, 방식, 수량, 상태, 체결 수량, 평균 체결가, 수수료, 세금 |

- 페이지는 GET `/`에만 답하고(다른 경로 404, GET이 아닌 요청 501), 파일을 바꾸지 않으며, 파일에서 읽은 글자는 이스케이프한다. 계좌번호, `account_seq`, 토큰은 보이지 않는다.
- 서버의 `127.0.0.1:8081`에서만 연다. v4와 같은 포트다.

## 컨테이너

- `compose.yaml`에 서비스 `v5`를 더한다. `v4`와 같은 빌드와 연결(`data/`, 읽기 전용 `.env`, `~/.trading-oracle/auth/`), `profiles: ["v5"]`, 명령 `rt-trading v5-serve --host 0.0.0.0`, 포트 `127.0.0.1:8081:8081`, `restart: unless-stopped`다.
- 다른 명령은 돌고 있는 컨테이너에서 `docker compose exec v5 rt-trading <명령>`으로 부른다.

## 가상 fixture

- 실행 차례 사례: v5 기간의 정상일·10시 개장일·수능일과 휴장일·주말에 아침·판단 차례와 실행기 켜는 시각(o − 15분)·끝(c + 10분)을 적는다.
- 실행기 돌보기 사례: 가짜 시계와 가짜 프로세스(정해 둔 시각에 끝남), 가짜 `days` 기록으로, 켜기·일찍 끝난 뒤 30초 뒤 다시 켜기(c + 10분 뒤 포함)·`end` 기록 뒤 켜지 않기·자정 뒤와 휴장일, v5 시작일 전에 켜지 않기를 적는다. 판단 명령이 실행 중일 때도 실행기가 켜져 있다.
- 페이지 사례: `live.sqlite3`(그날 설정, 장부, 주문, 정지, 한도, 장부와 다른 실계좌 수량이 담긴 차례)와 v5 `paper.sqlite3`, `v5-*` 보고서, 실행 기록을 만들고, 가짜 계좌번호·토큰 문자열을 저장 상태에 섞어 둔다. 판단 이유와 정지 이유에 `<script>`를 넣는다.

## 필수 Acceptance

SPEC 9절의 "실행 환경" 항목을 맡는다.

- 실행기가 거래일 o − 15분에 켜지고, 그날 `end`를 마쳤다는 기록이 생기면 다시 켜지지 않으며, 판단 명령이 도는 동안에도 함께 돈다. `end` 전에 끝나면 30초 뒤 다시 켜지고(c + 10분이 지난 뒤에도), 자정이 지나거나 휴장일·주말·v5 시작일 전이면 켜지지 않는다. 아침·판단 차례가 정상일·10시 개장일·수능일에 맞다(v4 사례에서 옮긴 사례).
- `GET /` 페이지에 그날 방식, 정지 상태와 이유, 봇 보유·현금·자산·수익과 가격, 실계좌 대조 결과(`장부와 다름` 포함), 한도 상태, 오늘 차례와 오늘 봇 주문, `v5-*` 최신 보고서의 헤드 계좌 칸이 나오고, 계좌번호·`account_seq`·토큰은 없다. 이유 속 `<script>`는 글자로 보이고, 다른 경로는 404, POST는 501이며, 페이지를 열어도 파일이 바뀌지 않는다(v4 사례에서 옮긴 사례). web 스펙의 서버 밖 파일·스크립트 금지가 이 페이지에도 맞다.

- 위 넘어오기 절차의 연습 운용 1거래일을 사고(안전 정지, 장부와 실계좌 차이) 없이 마치고, 실주문 점검을 마친다.
