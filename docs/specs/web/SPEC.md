# rt-trading web SPEC: 현황 웹페이지 모양
> **상태**: 승인(2026-11-04, 사용자가 정한 대로 오라클 검토 통과로 승인). 사용자 요청("html 좀 이제 보기 좋게 꾸며줘", 지금 가진 종목과 지금 수익도 보이게)으로 쓴다.

상위 문서: [intent.md](../../../intent.md) · 바꾸는 페이지: [v4 PRD 05](../v4/prds/prd05-server.md)의 현황 웹페이지

v4 현황 웹페이지는 글자 줄과 테두리 표만 있어 한눈에 읽기 어렵고, 헤드 계좌가 무엇을 들고 있는지와 수익이 몇 원인지 보이지 않는다. 이 스펙은 같은 페이지를 다시 꾸민다. 맨 위에 요약 칸을 두고, 헤드 계좌의 보유 종목과 수익을 보이며, 판단 차례마다의 상태를 색 칸으로 보이고, 표와 숫자를 읽기 쉽게 한다.
자동 실행과 판단·정산·보고서는 바꾸지 않고, 페이지는 v4가 이미 만드는 파일만 읽는다. v5 현황 페이지도 이 모양을 쓴다(v5 SPEC 8절).

## 0. 완결성 계약

- 바꾸는 것은 v4 현황 웹페이지(`v4-serve`의 `GET /`)의 HTML과 모양, 헤드 계좌의 보유 종목과 수익(원) 표시다. 보유를 보이려고 최신 보고서 폴더의 `trades-head.csv`(v4 보고서가 이미 만드는 헤드 계좌 체결 내역)를 더 읽는다. v3 페이지, 자동 실행, 판단·정산·보고서는 바꾸지 않는다.
- v4 PRD 05가 정한 페이지의 글자와 표의 행은 그대로 둔다. `v4-acceptance`의 현황 페이지 사례가 바꾸지 않은 채로 통과한다.
- 페이지는 서버 밖의 파일(글꼴, 스크립트, 그림, 스타일)을 불러오지 않고 자바스크립트를 쓰지 않는다. SSH 터널로만 보는 개인 페이지이고, v5부터는 계좌 정보가 실리기 때문이다(intent: 증권사 데이터는 제3자에게 주지 않는다).
- `uv run rt-trading web-acceptance`는 네트워크 없이 5절의 기준을 실행한다. 모두 통과하면 exit 0이다.
- 서버의 v4 컨테이너에 배포하고(6절) 사용자가 SSH 터널로 보고 확인하면 완료다.

## 1. 목표와 비목표

### 목표

- 페이지를 열면 맨 위 요약만 보고 자동 실행, 기간과 정산, 헤드 계좌, 판단 실패 수를 안다.
- 헤드 계좌가 어떤 종목을 몇 주 들고 있는지(또는 현금인지)와 수익이 원과 %로 얼마인지 안다. v4 모의 계좌는 다음 거래일 아침 정산 때 계산하므로 정산한 마지막 날 마감 기준이고, 그 날짜를 함께 적는다.
- 기간의 판단 차례마다 상태를 색으로 보고, 실패한 차례를 바로 찾는다.
- 표와 숫자를 읽기 쉽게 한다. 숫자는 오른쪽 정렬, 수익률은 색, 긴 이유는 줄바꿈이다.
- 맥북과 휴대폰 너비, 밝은 화면과 어두운 화면 설정에서 모두 읽힌다.

### 비목표

- 그래프, 장중 실시간 계좌 계산. 실시간 보유와 수익은 v5 현황 페이지의 실계좌 묶음에서 본다(v5 SPEC 8절).
- 웹에서 실행·중지·설정 바꾸기. 페이지는 보기 전용이다.
- 60초마다 새로 고치는 방식 바꾸기
- v3 페이지 바꾸기

## 2. 페이지 구성

위에서부터 다음과 같다. v4 PRD 05가 정한 내용의 순서(자동 실행, 기간, 오늘 판단, 판단, 계좌, 최근 실행 기록)는 그대로이고 새 묶음이 그 사이에 들어간다. 자동 실행과 기간은 요약 칸이 되므로 v4의 묶음 제목 구조는 바뀐다.

| 묶음 | 내용 | 바뀌는 것 |
| --- | --- | --- |
| 머리 | 제목 `rt-trading v4 모의 운용 현황`, `60초마다 새로 고침` | 모양 |
| 요약 칸 | 칸 네 개: 자동 실행, 기간, 헤드 계좌, 판단 | 자동 실행·기간 칸은 v4의 두 묶음을 칸으로 옮긴 것이다. 헤드 계좌·판단 칸은 새로 생긴다 |
| 판단 지도 | 기간의 거래일마다 한 줄, 그날의 판단 차례마다 색 칸 하나 | 새로 생긴다 |
| 오늘 판단 | v4와 같다 | 모양 |
| 판단 | v4와 같다 | 모양 |
| 계좌 | v4와 같다. 수익률에 색 | 모양 |
| 최근 실행 기록 | v4와 같다 | 모양 |

### 2.1 요약 칸

| 칸 | 보이는 것 |
| --- | --- |
| 자동 실행 | v4 자동 실행 묶음의 네 줄(상태, 마지막 실행, 다음 실행, 페이지 시각). 실행 중이면 상태를 강조하고, 마지막 실행에 0이 아닌 종료 코드나 시간 초과가 있으면 그 줄을 경고 색으로 한다 |
| 기간 | v4 기간 묶음의 두 줄과 정산 진행 막대(정산한 날 수 ÷ 기간 거래일 수) |
| 헤드 계좌 | 계좌 묶음과 같은 최신 보고서의 `head` 계좌: `{최종 자산}원`(크게), `수익 {+0}원 ({+0.00%})`, `보유: {종목 이름} {수량}주` 또는 `보유: 현금`, `{정산한 마지막 날} 마감 기준`, `최대 낙폭 {0.00%} / 기준 20%`와 그 비율의 막대. 보고서가 없으면 `보고서 없음` |
| 판단 | `판단 실패 {n}번`(크게), `ok {a}번`, `capped {b}번`, `지난 차례 {m}개`, `통과 기준: 기간 {N}차례 모두 ok·capped`(N은 기간 거래일의 판단 차례 수) |

- 지난 차례는 기간의 거래일 중 오늘까지의 판단 차례(v4 PRD 02) 가운데 판단 행이 있거나 페이지 시각이 마감 이후(페이지 시각 ≥ 마감)인 차례다.
- 판단 실패는 지난 차례 가운데 판단 행의 상태가 `late`·`invalid`·`failed`·`missing`인 차례와, 판단 행이 없는 차례(페이지에서 `없음`으로 보이는 차례)다. 마감 전에 기록된 실패도 센다. `capped`는 실패가 아니다(v4 SPEC 6절). `ok`·`capped` 수도 지난 차례에서 센다.
- 판단 실패가 0번이면 좋음 색, 1번 이상이면 나쁨 색이다.
- 헤드 계좌 칸은 계좌 묶음과 같은 보고서(`data/reports/`의 `v4-*` 중 이름순으로 가장 뒤의 것)를 읽는다. 그 보고서를 읽지 못할 때의 동작은 v4 페이지와 같다.
- 수익(원)은 최종 자산 − 시작 자금(500,000원, v4 SPEC 2절)이고, %는 보고서의 총수익이다. 둘 다 2.3의 수익률 색이다. 0이면 부호 없이 `수익 0원 (0.00%)`이다.
- 보유는 같은 보고서 폴더의 `trades-head.csv`의 마지막 체결로 정한다. 매수면 그 종목과 수량, 매도거나 체결이 없으면 현금이다. 파일이 없으면 `보유: 기록 없음`이다. 종목 이름은 069500이 KODEX 200, 114800이 KODEX 인버스다.
- 기준 날짜는 `report.json`의 `run.settled_through`(정산한 마지막 날)다. 없으면 기준 줄을 적지 않는다.

### 2.2 판단 지도

- 기간의 거래일마다 한 줄이다. 줄 앞에 날짜와 요일을 적고, 그날의 판단 차례마다 칸 하나에 차례 시각과 그 아래 `{상태} · {부하 id}`(부하가 없으면 상태만)를 적는다. 이유는 적지 않는다(오늘 판단·판단 표에 있다).
- 지도 위에 색 설명(정상, 교체 한도로 기록만, 실패, 대기)을 한 줄로 둔다.
- 판단 행이 없는 차례는 마감 전이면 `대기`, 마감이 지났으면 `없음`이다. 오늘 뒤의 거래일도 그날의 장 일정대로 칸을 그리고(10시 개장일은 여섯 칸, 수능일은 일곱 칸) 모두 `대기`다.
- 칸과 날짜는 표 칸(`<td>`)이 아닌 요소로 만든다. v4 페이지 사례가 지난 판단 표에 오늘 날짜 칸이 없는지를 `<td>`로 보기 때문이다.

### 2.3 색

| 상태 | 구분(HTML class) | 색 |
| --- | --- | --- |
| `ok` | `good` | 초록 |
| `capped` | `warn` | 노랑 |
| `late`, `invalid`, `failed`, `missing`, `없음` | `bad` | 빨강 |
| `대기` | `wait` | 회색 |

- 상태 색은 칸의 바탕색으로 칠하고, 색과 함께 상태 글자를 적어 색을 구분하지 못해도 읽힌다.
- 수익률은 한국 시세 화면 관례대로 플러스는 빨강, 마이너스는 파랑, 0은 기본 색의 글자 색이다. 바탕색인 상태 색과 섞이지 않게 글자에만 쓴다.

## 3. 모양 규칙

- 글꼴은 기기에 있는 시스템 글꼴(Apple SD Gothic Neo, 맑은 고딕, Noto Sans KR 등)이다. 숫자는 폭이 같은 숫자로 보인다.
- 페이지 폭은 가운데 최대 1100px이다. 요약 칸은 화면 너비에 따라 한 줄에 네 개에서 한 개까지 늘어선다.
- 표는 머리줄 바탕색과 줄 구분선을 두고, 숫자 열은 오른쪽 정렬, 이유 열은 줄바꿈한다. 좁은 화면에서는 표만 옆으로 넘긴다.
- 밝은 화면과 어두운 화면 설정(`prefers-color-scheme`)을 따른다.
- 스타일은 페이지 안의 `<style>` 하나에 둔다. 요소에 `style` 속성을 쓰지 않고, 막대는 `<progress value max>`로 그린다. 스타일과 칸·막대·색 칸을 만드는 함수는 v5 페이지도 쓰도록 모듈 하나(`src/rt_trading/web.py`)에 둔다.
- 판단 이유, 부하 id, 실행 기록처럼 파일에서 읽은 글자는 v4처럼 모두 HTML 이스케이프한다.

## 5. Acceptance Criteria

`web-acceptance`는 임시 디렉터리에 기간 설정, 판단 기록(모든 상태, 마감 전·뒤의 행 없는 차례 포함), 이름이 다른 보고서 두 개(헤드 계좌 체결 내역 포함), 실행 기록을 만들고 가짜 시각으로 v4 페이지를 만든다. 기대값은 손으로 정한다.

- 요약 칸이 자동 실행, 기간, 헤드 계좌, 판단 순으로 있고, 정산 막대와 낙폭 막대의 비율이 손으로 정한 값과 같다. 판단 칸의 판단 실패 수가 지난 차례 가운데 `late`·`invalid`·`failed`·`missing` 행과 행 없는 차례를 센 값이고, `capped`와 마감 전의 행 없는 차례는 세지 않는다. 판단 지도는 기간 거래일마다 한 줄이고, 칸마다 차례 시각, 상태, 부하와 구분(`good`·`warn`·`bad`·`wait`)이 손으로 정한 값과 같다.
- 헤드 계좌 칸이 이름순으로 가장 뒤의 보고서의 `head` 계좌 값(최종 자산, 수익 원과 %, 기준 날짜)과, 그 폴더 `trades-head.csv`의 마지막 체결로 정한 보유를 보인다. 매수·매도·매수로 끝나는 내역이면 마지막 매수의 종목 이름과 수량, 매수·매도로 끝나는 내역이면 현금이다. 옛 보고서나 다른 계좌의 값이 아니다. 수익이 0이면 `수익 0원 (0.00%)`이다. `trades-head.csv`가 없으면 `보유: 기록 없음`이고, `report.json`에 `run`이 없으면 `마감 기준` 줄이 없다.
- 페이지를 HTML 파서로 읽으면 `script`·`link`·`img`·`iframe`·`object`·`embed` 태그, `src`·`href`·`style` 속성, `on`으로 시작하는 속성, 값에 `javascript:`가 든 속성이 없다. `<style>`은 하나이고 그 안에 `@import`와 `url(`이 없다.
- `uv run rt-trading v4-acceptance`가 그대로 통과한다(페이지의 글자·표 행, 이유 속 HTML 이스케이프, GET만 받음, 페이지를 열어도 파일이 바뀌지 않음).

## 6. 배포

- 사용자 승인 뒤 배포한다.
- v4 모의 운용 기간(2026-11-02~11-06) 중에는 그날 마감 전 판단(15:10 차례)이 끝난 뒤부터 다음 거래일 07:25 전까지만 배포한다. 서버에서 돌고 있는 코드에 이 스펙의 변경만 더한 커밋을 받아 `docker compose up -d --build v4`로 다시 만든다.
- 지시문, 입력 항목, 검색어, 판단 시각, 부하, 모델을 바꾸지 않으므로 v4 기간을 다시 세지 않는다(v4 SPEC 6절). 다시 켠 뒤 페이지의 마지막 실행은 `없음`으로 시작한다.
